# 議会だより 原稿編集ツール

各議員からばらばらの様式で届く原稿を、**校正・要約し、写真を配置して、
Word の様式に流し込む**までを支援するツールです。

**インターネットにつながずに動きます。** 原稿・写真・議員名などの情報が
外部に送信されることは一切ありません。通信するのはこのパソコンの中
（127.0.0.1）だけです。

---

## できること

| 手順 | やること | ツールがやってくれること |
|---|---|---|
| ① | 号を作る | 1号ぶんの作業をフォルダ1つにまとめて保存 |
| ② | 原稿を集める | Word・テキスト・PDF・リッチテキストを様式を問わず取り込み、文字コードも自動判別 |
| ③ | 校正・要約 | 誤字脱字・表記ゆれ・固有名詞の誤記を指摘。枠の字数に合わせて要約 |
| ④ | 写真 | 向きの補正、枠の縦横比に合わせた切り出し、印刷解像度の判定 |
| ⑤ | 様式に流し込む | 前号の Word をそのまま様式として使い、レイアウトを崩さず中身だけ差し替え |
| ⑥ | 書き出し | 差し込み済みの Word（必要なら PDF）を出力 |

## 使いはじめる

### 必要なもの

- **Python 3.10 以降**（必須）
  Windows: <https://www.python.org/downloads/windows/>
  インストール時に **「Add Python to PATH」に必ずチェック**を入れてください。

- **Pillow**（推奨）— 写真の切り出し・向き補正・解像度チェックに使います
- **PyMuPDF**（任意）— PDF で届いた原稿を読むときに使います
- **LibreOffice**（任意）— 旧形式（`.doc`）の読み込みと PDF 書き出しに使います
  <https://ja.libreoffice.org/download/>

追加分をまとめて入れる場合は、**`追加部品のインストール.bat` をダブルクリック**してください
（この作業のときだけインターネットに接続します）。手動で入れる場合:

```
pip install -r requirements.txt
```

※ 何も入れなくても、`.docx`・テキスト原稿の取り込みと Word への差し込みは動きます。

### 起動と終了

#### はじめに一度だけ

Windows では `デスクトップにアイコンを作る.bat` をダブルクリックしてください。
デスクトップに専用アイコンのショートカットができます。以後はそれを
ダブルクリックするだけで起動できます。

> うまくいかない場合は、`起動.bat` を右クリック →「送る」→
> 「デスクトップ (ショートカットを作成)」でも作れます。できた
> ショートカットのプロパティから「アイコンの変更」で `icon.ico` を
> 選んでください。

#### 起動

- **Windows** — デスクトップのアイコン（または `起動.bat`）をダブルクリック
- **macOS / Linux** — `./start.sh`
- 手動 — `python app.py`

ブラウザが自動で開きます。開かないときは
`http://127.0.0.1:8730/` をブラウザに貼り付けてください。

**黒い画面は、起動が終わると自動で閉じます。** 本体は画面を出さずに
動き続けるので、そのまま使えます。

すでに起動しているときにもう一度アイコンを押しても、二重には
起動しません。ブラウザで画面が開くだけです。

#### 終了

**画面右上の「終了」ボタン**を押してください。黒い画面が出ていないため、
これが通常の終わり方になります。

うまく終われないときは `終了.bat` をダブルクリックしてください。
（コマンドで終わらせる場合は `python app.py --quit`）

> 終了せずにパソコンを終了しても、データは失われません。
> 編集内容は「保存」を押した時点でフォルダに書き込まれています。

### 保存先フォルダ

作業データは **デスクトップの「議会だより」フォルダ** に保存されます。
フォルダが無ければ起動時に自動で作られます。

デスクトップの場所は次のように調べるので、OneDrive にデスクトップが
移されている場合や、Mac・Linux でも正しい場所に作られます。

| OS | 調べ方 |
|---|---|
| Windows | レジストリの Shell Folders（OneDrive へのリダイレクトに対応） → `%USERPROFILE%\Desktop` |
| macOS | `~/Desktop` |
| Linux | `~/.config/user-dirs.dirs` の `XDG_DESKTOP_DIR` → `~/Desktop` → `~/デスクトップ` |

保存先を変えたいとき:

```
python app.py --workspace "D:\議会だより"
```

指定した場所に作れなかったとき（権限が無い、ドライブが無いなど）は、
ホームフォルダの下に切り替えて起動を続けます。切り替えたことは
起動時の黒い画面に表示されます。

## 進め方

### ① 号を作る

「第204号」のように名前をつけて作成すると、保存先フォルダの下に
次の構成でフォルダができます。

```
第204号/
  project.json      記事・割付・設定（作業データ）
  template.docx     様式（Word）
  manuscripts/      議員から届いた原稿の原本
  photos/           写真の原本
  出力/             差し込み済みの Word / PDF
  user_dict.json    この号だけの固有名詞辞書
```

**このフォルダごとコピーすれば、別のパソコンに作業を引き継げます。**
共有フォルダに置いて交代で編集する運用もできます（同時編集はできません）。

### ② 原稿を集める

届いたファイルを画面にドラッグ＆ドロップするだけです。

- `.docx` — 本文・表・テキストボックスの中身まで拾います。埋め込み写真も取り込みます
- `.doc` — LibreOffice があれば読めます。無い場合は Word で `.docx` に保存し直してください
- `.txt` — Shift-JIS（CP932）・UTF-8・EUC-JP を自動判別します
- `.pdf` — PyMuPDF があれば読めます（スキャンした画像だけの PDF は読めません）
- `.rtf` — 書式を捨てて文字だけ取り出します
- メール本文などは「直接貼り付ける」欄に貼れます

取り込むときに、次の整形を自動で行います（設定で切り替えられます）。

- 半角カナ → 全角
- 句読点・括弧を全角に統一
- 全角英数字 → 半角
- **数字を縦書きの慣行に合わせる**（1桁は全角「４月」、2桁以上は半角「12日」）

1行目が短く句点で終わっていない場合は、**見出しとみなして本文から切り出します**。
違っていた場合は、③の画面で「取り込んだ原稿に戻す」を押せば元に戻せます。

### ③ 校正・要約

#### 校正

「校正する」を押すと、次の観点で指摘が出ます。

| 種類 | 例 |
|---|---|
| **表記ルール** | 等 → など、ひとつ → 一つ、様々 → さまざま、子供 → 子ども、〜にて → 〜で |
| **明らかな誤字** | 週知 → 周知、絶対絶命 → 絶体絶命、話しをする → 話をする |
| **同音異義語** | 追求／追及／追究、保証／保障／補償、施行／施工 の使い分け確認 |
| **文法** | ら抜き言葉（見れる → 見られる）、助詞の重複、さ入れ言葉 |
| **記号・数字** | 半角カナ、括弧の対応、機種依存文字（①㈱№）、数字の全角半角 |
| **読みやすさ** | 1文が長すぎる、「が、」の多用、「の」の連続 |
| **ルビ** | 浚渫・暗渠・分賦金などの難読語に読み仮名を提案 |
| **固有名詞** | 山崎 → 山﨑、尾崎 → 尾﨑 など、字形の似た漢字の取り違え |

指摘は3段階で色分けされます。

- **要修正**（赤）— 明確な誤りです
- **確認**（橙）— ハウスルールに合っていない可能性があります
- **参考**（青）— 直すかどうかは編集判断です

「自動で直せる◯件をまとめて修正」で一括修正できます。
**同音異義語とルビの提案は自動修正しません**（文脈によって正解が変わるため）。

> 表記ルールは第203号の Word 原稿と印刷版を突き合わせて、
> 実際に行われている書き換えをそのまま入れてあります。
> 自治体ごとのルールに合わせて `gikai/data/style_rules.json` を編集してください。

#### 字数を枠に合わせる

枠の「1行の字数」と「行数」を入れると、本文の字数・行数が
リアルタイムで表示され、あふれると赤くなります。

字数を減らす方法は2段階あります。

1. **「冗長表現を縮める」** — 意味を変えずに短くします。
   「対応することができる」→「対応できる」、「〜ということである」→「〜という」など。
   **内容は落ちません。**まずこちらを試してください。

2. **「枠に合わせて要約」** — 1で足りないとき、重要度の低い文を落とします。
   各段落の先頭文は優先的に残します。

どちらも、**反映する前に左右の比較画面が出ます。**
機械的な処理なので、必ず内容を確かめてから反映してください。

「見出し候補」を押すと、本文から見出し・リード文の候補を作ります。
そのまま使わず、必ず手直ししてください。

### ④ 写真

写真をドラッグ＆ドロップすると、次を自動で行います。

- **EXIF の回転情報を反映**（スマホで撮った写真が横倒しにならないように）
- **印刷解像度の判定** — 350dpi で刷ったときに何 cm まで使えるかを表示します。
  小さすぎる場合は「元データをもらってください」と警告します
  （メールで縮小された写真は印刷に使えません）
- **枠の縦横比に合わせた切り出し** — 差し込み先を選ぶと、その枠の比率に
  合わせて中央（人物写真を想定して少し上寄り）を切り出します。
  「切り出し確認」で結果を確認できます

説明文（キャプション）と撮影者も、ここで入力しておきます。

### ⑤ 様式に流し込む

#### 様式の読み込み

**前号の Word ファイルをそのまま様式として使えます。**
レイアウト（段組み・縦書き・色・罫線・写真の枠）には一切手を加えず、
**文字と写真の中身だけを差し替えます。**

`.doc` のままでも、LibreOffice があれば自動で変換します。
無い場合は Word で「名前を付けて保存 → Word 文書（.docx）」してください。

#### 差し込み先の指定

読み込むと、様式の中の文字が入る場所が **枠（スロット）** として一覧に出ます。
「頁」「いまの中身（前号）」「字数」を見ながら、どの記事をどの枠に
入れるかを選びます。枠の字数は、その記事の**字数上限として自動で引き継がれます**。

より確実に指定したい場合は、**差し込みマーカー**が使えます。
Word 側で、差し替えたい場所に次のように書いておくだけです。

```
{{記事1_見出し}}
{{記事1_本文}}
{{写真1_説明}}
```

マーカーがあると、枠の中のその部分だけが差し替わります。
様式を作り直しても番号がずれないので、**毎号使い回す様式にはこちらを推奨します。**

### ⑥ 書き出し

「Word に書き出す」で、`出力/` フォルダに差し込み済みの Word ができます。

- 差し込み先が未設定の記事があれば警告します
- LibreOffice があれば PDF も同時に作れます（Word の「PDF として保存」でも同じです）
- 「紙面プレビュー」は縦書きの下見用です。**最終的な色・罫線は様式が持っている**ので、
  仕上がりの確認は書き出した Word を Word で開いて行ってください

書き出したあとの手順:

1. Word で開く
2. 枠からあふれた文字がないか、見開きで確認する（あふれたら③に戻って詰める）
3. そのまま印刷所に渡す

## 自治体に合わせて調整する

### 固有名詞辞書（画面から編集できます）

右上の「設定」→「この号だけの固有名詞辞書」に、議員名・地名・施設名・
課名を1行ずつ入れてください。ここに登録した語と**1文字だけ違う**表記が
原稿にあると、誤記の可能性として指摘します。

全号で共通に使う語は `gikai/data/local_terms.json` に書いてください。
初期状態では日高村の議員名・地名・課名が入っています。**他の自治体で使う場合は
このファイルを差し替えてください。**

### 表記ルール

`gikai/data/style_rules.json` を編集します。

```json
{ "find": "等", "to": "など", "severity": "warn",
  "note": "本誌は「等」を「など」に開く",
  "context_exclude": ["平等", "等級"] }
```

- `severity` — `error`（要修正）/ `warn`（確認）/ `info`（参考）
- `context_exclude` — 前後にこの語があるときは指摘しない
- `to` に `／` を含めると、自動修正の対象から外れます（人が選ぶべき場合）

### 難読語のルビ

`gikai/data/ruby.json` に「語」と「読み」を追加してください。

### 同音異義語

`gikai/data/confusions.json` の `pairs` に追加してください。

```
gikai_editor/
  app.py                          起動用
  起動.bat                        起動（Windows・終わると自動で閉じる）
  終了.bat                        終了（Windows）
  デスクトップにアイコンを作る.bat   ショートカット作成（Windows）
  追加部品のインストール.bat        Pillow / PyMuPDF の導入（Windows）
  start.sh                        起動（macOS / Linux）
  icon.ico / icon.png             アイコン
  tools/make_icon.py              アイコンを作り直すとき
  requirements.txt
  gikai/
    textutil.py         日本語の正規化・字数計算・文分割
    importers.py        原稿の取り込み（docx / doc / txt / pdf / rtf）
    proofread.py        校正エンジン
    summarize.py        要約・字数調整
    photos.py           写真の切り出し・解像度判定
    docxio.py           Word 様式のスロット検出と差し込み
    preview.py          紙面プレビュー（HTML）
    project.py          プロジェクト（1号ぶんの作業データ）
    workspace.py        保存先フォルダの決定（デスクトップ配下）
    runstate.py         起動中かどうかの記録
    server.py           ローカル専用サーバ
    data/               辞書（表記ルール・固有名詞・難読語・同音異義語）
    static/             画面（HTML / CSS / JavaScript）
  tests/test_all.py     テスト
```

テストの実行:

```
python tests/test_all.py
```

## よくある質問

**Q. 本当にオフラインで動きますか。**
はい。サーバは `127.0.0.1`（このパソコン自身）だけで待ち受けます。
外部のホスト名でアクセスされた場合は拒否します。
画面も外部の CSS やフォントを読み込みません。ネットワークを
切断した状態でも、すべての機能が動きます。

**Q. 要約はどのくらい信用できますか。**
文の重要度を計算して選ぶ方式（抽出型）で、**文章を作り直すことはしません**。
残った文はすべて原稿にあった文そのものなので、事実が変わることはありませんが、
**文脈がつながらなくなることはあります。**必ず目で確認してください。
言語モデルは使っていません（オフラインで動かすため）。

**Q. 校正で見落としはありますか。**
あります。辞書に無い誤字や、文脈依存の誤りは検出できません。
**人の校正を置き換えるものではなく、機械的に見つかるものを先に潰して、
人の目を内容の確認に回すための道具**と考えてください。

**Q. Word のレイアウトが崩れませんか。**
差し込みは、段落の書式（フォント・サイズ・縦書き・字下げ）を保ったまま
文字だけを入れ替えます。枠・段組み・図の位置には触れません。
ただし **文字数が増えれば枠からあふれます。**③の字数表示で
枠に収まる長さにしてから書き出してください。

**Q. 複数人で同時に編集できますか。**
できません。1つの号は1人ずつ編集してください。
フォルダをコピーして渡す形で分担することはできます。

**Q. 前の状態に戻せますか。**
記事ごとに「取り込んだ原稿に戻す」で、取り込んだ直後の状態に戻せます。
原稿の原本は `manuscripts/` に、写真の原本は `photos/` にそのまま残ります。
書き出した Word は毎回 `出力/` に作られるので、上書き前のものを残したい場合は
書き出し時にファイル名を変えてください。
