# 出力テンプレート

そのまま社内に貼れる形にする。見出しは職場の慣習に合わせて `report.config.json` の `template` で差し替え可能。

## 日報

会議が業務の中心なので、**会議を先頭に置く**。各会議は「出た」ではなく「決まったこと・引き受けたこと」を書く。

```markdown
# 日報 2026-08-28（金）

## 会議・打ち合わせ

### 16:00–17:00 議会運営委員会
- 決定：〇〇の日程を9月第2週に変更
- 自分のアクション：△△の資料を9/3までに作成
- 持ち越し：□□の取り扱いは次回に再協議

### 09:30–10:30 AI研修
- （内容未整理）

## その他の業務
- （会議以外で進めたこと。1行1成果。無ければセクションごと省く）

## 明日の予定
- （翌営業日の予定と締切。休日を挟む場合は「翌営業日は8/31（月）」と明記）

## 課題・相談事項
- （ブロックされていること。無ければ「特になし」）
```

### 会議の書き分け

| 状況 | 書き方 |
|---|---|
| 録音があり要約が取れた | 決定 / 自分のアクション / 持ち越し の3点を書く |
| 録音はあるが決定事項が拾えない | 議題だけ列挙し `（決定事項なし）` |
| 録音が無い | 時刻と会議名のみ + `（内容未整理）` |
| 実行時刻より後に始まる | `※作成時点では開始前` を付け、実績として書かない |
| 機微な議題を含む | その部分だけ `（非公開の議題あり）` に置き換える |

## 週報

```markdown
# 週報 2026-08-24 〜 2026-08-28

## サマリ
（3行以内。今週何が前に進んだか、詰まっているものは何か）

## 主な会議と決定事項
- 8/26 〇〇委員会 — △△の方針を承認。□□は継続審議
- 8/28 議会運営委員会 — 日程変更を決定

## 進行中の案件

### 案件名
- （テーマ単位。日ごとに割らない）
- （数字が出せるものは数字で）

## 来週の予定
- （確定している会議・締切）

## リスク・課題
- （進行を脅かすもの。無ければ「特になし」）
```

## 末尾に必ず付けるもの

本文の後に、報告書の一部ではないメモとして付ける（コピペ時に外せるよう `---` で区切る）。

```markdown
---
### 確認してほしい点（報告書には含めない）
- （推定で書いた箇所）
- （情報が取れなかったソース）
- （機微情報のため意図的に省いた箇所）
```

## 文体

- 社内報告で一般的な**簡潔な体言止め・敬体混在**を既定とする。設定 `template.tone` で `formal` / `casual` に切り替え可能
- 「〜させていただきました」のような過剰な敬語は使わない
- 一人称は書かない（「私は」を省く）
- 会議の決定事項は「〜することとした」「〜に決定」と、主体をぼかさず簡潔に
