# データ収集手順（朝のブリーフ）

**カレンダー → 期限データ → メール → 持ち越し**の順に集める。各ソースは独立で、1つ失敗しても他を続行し、失敗は成果物末尾に明記する。

## 共通：MCPツールの探し方

コネクタのMCPサーバー名はセッションごとに変わる。**ツール名を決め打ちしない。**
`ToolSearch` でキーワード検索し、その回で有効なツール名を確認してから呼ぶ。

```
ToolSearch("calendar list events")
ToolSearch("gmail search threads")
```

見つからなければ、そのソースはスキップして「コネクタ未接続」と記録する。

---

## 1. カレンダー（今日の予定）— 主軸

1. 対象日の 00:00〜23:59（`calendar.timeZone`、既定は `Asia/Tokyo`）で予定を取得する
2. `calendar.excludePatterns` に一致するタイトルは落とす（移動・ランチ・ブロック時間など）
3. 辞退した予定（`excludeDeclined`）は落とす。**自分で登録した予定（参加者が空）は落とさない**
4. 同一時刻・同一タイトルの重複は名寄せする
5. 終日予定は、タイトルに「締め切り」「期限」を含むものだけ「期限が来るもの」に回す

各予定から取り出すもの：開始・終了時刻、タイトル、場所（オンラインかどうか）、説明欄に添付資料や事前準備の記載があればその要点。

**現在時刻より前に始まった予定は「開始済み」として分ける。**

## 2. 期限データ（書類・回覧）

`data/deadlines.json` があれば読む。これは `apps/docs-tracker/index.html`（書類・回覧の期限トラッカー）から「JSONで保存」で書き出したファイル。

```json
{ "v": 1, "items": [
  { "title": "…", "kind": "提出", "dest": "総務課", "dueOn": "2026-09-05",
    "status": "未着手", "priority": "高", "note": "" }
] }
```

- `status` が `完了` のものは除く
- 期限（`dueOn`）が **超過・今日・3日以内**のものだけ載せる。`brief.deadlines.lookaheadDays` で日数を変えられる
- ファイルの更新日時（`ls -l` などで確認）が前日より古ければ、`※期限データは M/D 時点` と明記する

`data/fridge.json`（冷蔵庫アプリの書き出し）があり、`brief.fridge.enabled` が true のときは、期限切れ・当日期限の食材だけを最後に1行で添える（買い物の判断に使うため）。無ければ何も書かない。

## 3. メール（要対応のもの）

**読むだけ。既読化・返信・ラベル付け・アーカイブはしない。**

1. `brief.mail.query` の条件で検索する（既定：`is:unread newer_than:3d -category:promotions -category:social`）
2. 取得するのは**スレッド一覧と件名・差出人まで**。本文は、件名だけで用件が判断できないときに限り開く
3. 次のものは落とす：自動送信（`noreply` / `no-reply` / `notifications@`）、メールマガジン、システム通知、自分が送信したもの
4. 残ったものを「自分の返答・作業を待っているか」で絞る。最大 `brief.mail.maxItems` 件（既定5件）

書くときは **件名の要点を1行**にまとめる。本文の引用、個人情報、金額条件は書かない。差出人は組織名・役職で表す。

## 4. 持ち越し（前日の日報）

`reports/daily/` の直近のファイル（対象日より前で最新のもの）を読む。

- 「明日の予定」「課題・相談事項」セクションから、**まだ終わっていないもの**を拾う
- 同じ内容が今日のカレンダーや期限データにもある場合は重複させない（カレンダー側を優先）
- 日報が無ければこのセクションは省く

## 5. GitHub（任意）

`brief.github.enabled` が true のときだけ。自分がレビュー依頼を受けている PR と、自分に割り当てられた期限付き Issue を拾う。開発作業がない日は空でよく、空なら見出しごと省く。
