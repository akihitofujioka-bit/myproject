# 朝のブリーフ生成

**今日これから何をするか**を1枚にまとめる。`/report`（日報）が一日の終わりに実績を振り返るのに対し、こちらは一日の始まりに段取りを組むためのもの。

## 大原則

1. **書き換えない。** メールの既読化・返信・アーカイブ、予定の変更・削除、ファイルの送信は一切しない。読み取り専用。成果物はローカルのMarkdownファイルのみ。
2. **事実を作らない。** 収集できなかったソースは「取得できず」と正直に書く。予定が少ない日は少ないまま出す。
3. **推測には印を付ける。** 件名や予定名から用件を補完した部分は `（推定）` を付ける。
4. **機微情報を持ち出さない。** メール本文の個人情報・評価・人事・金額条件はブリーフに転記しない。差出人は氏名ではなく組織名・役職で書く。
5. **優先順位を勝手に決めつけない。** 並べるのは「期限順」まで。何を先にやるべきかの判断はユーザーに委ねる。

## 手順

### 1. 日付と現在時刻を確認する

`TZ=Asia/Tokyo date` で今日の日付と現在時刻を取る。引数に日付があればその日、なければ今日。
**現在時刻は必須**。ブリーフは「これからの予定」と「もう終わった予定」を分けて書くため。

### 2. 設定を読む

リポジトリ直下の `brief.config.json` を読む。無ければ `.claude/skills/brief/config.example.json` の既定値で動く。
`author` と `calendar` は、`report.config.json` があればそれを既定値として読み、`brief.config.json` の同名項目で上書きする（設定の二重管理を避けるため）。

### 3. データを集める

`references/collection.md` の手順に従う。**カレンダー → 期限データ → メール → 持ち越し**の順。
各ソースは独立で、1つ落ちても他は続行し、落ちたソースは成果物の末尾に `（取得失敗: 〜）` と明記する。

### 4. 文章化する

以下の構成で書く。**該当が0件のセクションは見出しごと省く**（空の見出しが並ぶと読む気が失せる）。

```markdown
# 朝のブリーフ 2026-09-03（木）

> 作成時刻 08:12 ／ 予定 4件・締切 2件・要対応メール 3件

## 今日の予定
- 09:30–10:30 〇〇連絡会（庁内会議室A）※資料の事前確認あり
- 14:00–15:00 △△事業者との打ち合わせ（オンライン）
- 16:00–16:30 課内定例

## 期限が来るもの
- **【超過】** 職員研修 受講報告書（提出／総務課）— 2026-09-01 が期限（2日超過）
- **【今日まで】** 備品発注伺い（申請／会計課）

## 要対応のメール
- 〇〇課より「△△の照会について」— 回答期限 本日（推定）
- 事業者より「見積書送付の件」— 内容確認が必要

## 前日からの持ち越し
- ××の資料修正（前日の日報「課題・相談事項」より）

## 確認してほしい点
- 14:00 の打ち合わせは、前日の日報では 15:00 開始と書かれていました。どちらが正しいか確認してください。
```

書き方の要点：

- **予定は時刻順に、場所と「事前に要るもの」まで**。資料の準備が要る予定は、その旨を1行に含める。
- **すでに開始時刻を過ぎた予定は分けて書く**（`※作成時点で開始済み`）。朝以外に実行された場合に効く。
- **締切は「超過 → 今日 → 3日以内」の順**。超過は太字で目立たせる。
- **メールは用件を1行で**。本文の引用はしない。判断が要るものだけ載せ、通知・広報メールは落とす。
- 全体で 20行以内に収める。読むのに1分以上かかるブリーフは読まれない。

### 5. 出力する

- 保存先：`reports/brief/YYYY-MM-DD.md`
- 同じ日のファイルが既にあれば**上書きせず**、差分を見せて追記・置換どちらにするか聞く。
- 保存後、本文をそのままターミナルにも表示する。
- 最後に「確認してほしい点」を3つ以内で挙げる（ソース間で食い違った箇所、推定した箇所、取得できなかったソース）。

### Google Drive への保存（スマートフォンで読むため）

`output.drive.enabled` が true なら、ローカル保存に加えて Drive にも保存する。**朝のブリーフは通勤中にスマートフォンで読むもの**なので、この設定を既定で有効にしている。

- 保存先フォルダは `output.drive.folderId`
- タイトルは `朝のブリーフ 2026-09-03（木）` の形。**日付を含めて一意にする**
- `create_file` に `contentMimeType: "text/markdown"` を渡す（Googleドキュメントに変換され、見出しと箇条書きが書式として反映される）
- 同じ日のファイルが既にある場合は、`search_files` で `parentId = '<folderId>' and title = '<同じタイトル>'` を検索し、**内容に変化があるときだけ**古いファイルを `trash_file` して作り直す。変化がなければ何もしない

Drive のURLは毎回変わりうるので、本文にDriveリンクを埋め込まない。

## 毎朝の自動生成

平日の朝に自動で作りたい場合は Routines（スケジュール実行）に登録する。設定方法は `docs/routines-setup.md` を参照。

- 実行時刻は始業の1時間前を目安にする（予定の変更が反映されるため、前日夜より当日朝がよい）
- 自動実行でも**送信は行わない**。生成した本文とDriveの保存だけで止める

## よくある失敗

- **予定を全部並べる** → 移動・昼休み・ブロック時間は段取りに要らない。`calendar.excludePatterns` で落とす。
- **メールを全部載せる** → 通知・メルマガ・自動送信は落とす。「自分の返答を待っている人がいるか」だけが基準。
- **メールを既読にしてしまう** → 取得系のツールでも、既読化の副作用があるものは使わない。迷ったら開かずに件名だけで判断する。
- **昨日の日報をそのまま貼る** → 持ち越しは「まだ終わっていないもの」だけ。完了済みの項目は載せない。
- **期限データを鵜呑みにする** → `data/deadlines.json` は手動で書き出したファイル。**書き出し日時が古ければその旨を明記する**（例：`※期限データは 8/28 時点`）。
