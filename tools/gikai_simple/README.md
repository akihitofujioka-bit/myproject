# 議会だより かんたん原稿ツール

議会だよりの **原稿（文章）と写真の配置指示** を、誰でも同じ手順で作るための道具です。

- 画面は 1 つ。覚える操作は「区分を選んで書く」「写真を選んで入れる」「Word を作る」の 3 つ
- 出力は **原稿の Word（写真入り）** と **写真配置指示書の Word** の 2 つ。印刷所にはこれと写真フォルダを渡す
- **校正**（誤字脱字・表記ゆれ）と **文字数チェック**（枠に収まるか）が付いています
- 要約・議案の自動解析などは **しません**。Word 上で人が直す前提です
- インターネットに何も送りません（すべてこのパソコンの中で完結します）

同じフォルダにある `gikai_editor`（校正・自動組版まで行う多機能版）や、
`gikai_dayori_v5.8.pyw`（タブ式の編集支援ツール）を **小さく作り直したもの** です。
どちらも残してあります。

## 考え方 — 写真の場所は「原稿の中の 1 行」で表す

写真を入れたい場所に、原稿の中へ次の 1 行を書くだけです。

```
【写真】ファイル名.jpg｜中｜説明文
```

| 部分 | 意味 |
|---|---|
| `ファイル名.jpg` | 「写真」フォルダの中のファイル名 |
| `中` | 大きさ。**表紙**（A4 一面）／**大**（幅 80mm）／**中**（55mm）／**小**（38mm）／**顔**（26mm・顔写真）。省略すると 中 |
| `説明文` | 写真の説明（キャプション）。省略可 |

区切りは全角「｜」でも半角「|」でもかまいません。
この行は画面のボタンで入れられますが、メモ帳で手書きしても、消しても、別の場所に動かしても大丈夫です。
**ツールが無くても、原稿ファイルを見れば「どこにどの写真か」が分かる**のが狙いです。

## 1 号 = 1 フォルダ

```
第204号/
  号情報.json                    号数・発行日・号の種類
  01_表紙.txt                    区分ごとの原稿（番号の順 = 紙面の順）
  02_行政報告.txt
  03_審議したこと・決まったこと.txt
  04_閉会中の委員会活動報告.txt
  05_一般質問.txt
  06_特集.txt
  07_裏表紙.txt
  08_お知らせ.txt
  写真/                          写真の原本（印刷所にそのまま渡す）
  別添/                          賛否一覧表の Excel など、原稿以外で印刷所に渡すもの
  出力/                          第204号_原稿.docx、第204号_写真配置指示.docx
  はじめにお読みください.txt
```

このフォルダごとコピーすれば、別のパソコンや次の担当者に引き継げます。

## 号の種類（定例会ごとの構成）

区分は固定ではなく、**フォルダにある `番号_区分名.txt` がそのまま紙面の順** になります。
号を作るときに「号の種類」を選ぶと、その定例会に合った区分がそろいます
（第198〜201号の 1 年分から確認した構成です）。

| 号の種類 | 発行 | 毎号あるものに加えて |
|---|---|---|
| 3月号 | 4月末 | 当初予算の概要（各会計予算・注目する事業・繰越事業） |
| 6月号 | 7月末 | お知らせ |
| 9月号 | 10月末 | 決算の概要、議員行政視察研修報告、お知らせ |
| 12月号 | 1月末 | 行政視察・研修報告、お知らせ（特集は新年の抱負） |

毎号あるもの: 表紙 → 行政報告 → 審議したこと・決まったこと → 閉会中の委員会活動報告 → 一般質問 → 特集 → 裏表紙

### 作ったあとから号を変える

号数・発行日・号の種類を間違えても、上の **「号の情報を変える」** で直せます。

| 変えたもの | どうなるか |
|---|---|
| 号数 | `号情報.json` を直し、**フォルダ名も変えるか聞きます**（変えなくても作業は続けられます） |
| 発行日 | `号情報.json` を直します |
| 号の種類 | **足りない区分を足すか聞きます**（3月号→9月号なら「決算の概要」「議員行政視察研修報告」）。
その種類に無い区分は**そのまま残します**（原稿が入っているかもしれないため。要らなければ「外す」で） |

**原稿は消えません。** 区分を足すときも、フォルダ名を変えるときも、書いた内容はそのまま残ります。

> 表紙の原稿に書いた号数（「第２０４号」など）は**自動では直しません**。
> 人が書いた文章を勝手に書き換えないためです。号数を変えたら表紙も確かめてください。

区分は画面の **「区分を追加」「▲▼」「外す」** で足したり順番を変えたりできます
（外せるのは中身が空の区分だけ。ファイルの番号はツールが付け直します）。
区分を選ぶと「載せるもの」のヒント（前年の例）が原稿欄の上に出ます。

## 使いはじめる

### 必要なもの

- **Python 3.9 以降**（<https://www.python.org/downloads/windows/>。インストール時に「Add Python to PATH」にチェック）
- **python-docx**（Word を作る）と **Pillow**（写真の縮小表示・向き補正）

  ```
  pip install -r requirements.txt
  ```

  インターネットにつながらないパソコンでは、つながるパソコンで
  `pip download -d wheels python-docx Pillow` として作った `wheels` フォルダを持ち込み、
  `pip install --no-index --find-links=wheels python-docx Pillow` で入ります
  （Pillow だけなら `gikai_editor/wheels` にも Windows 用が同梱してあります）。

### 起動

- Windows: `起動.bat` をダブルクリック（または `app.pyw` をダブルクリック）
- macOS / Linux: `python3 app.pyw`

> macOS 付属の Python（Tk 8.5）では画面がうまく描かれません。Mac で使うときは
> python.org の Python 3.12 以降（Tk 8.6 付き）を入れてください。

## 使い方（5 つだけ）

1. **「新しい号を作る」** — 号数・発行日・号の種類を入れ、フォルダを作る場所を選びます
2. **左の区分を選び、中央に原稿を書く** — 議員から届いた `.docx`／`.doc`／`.txt` は「原稿ファイルを取り込む」で文字だけ貼り付きます
3. **「写真フォルダを開く」** で開いたフォルダに写真を入れ、「写真を読み直す」を押します
4. **写真を選び、大きさと説明を決めて「カーソル位置に入れる」** — 原稿に【写真】行が入ります。使用済みの写真は緑の枠になります
5. **「Word を作る」** — 出力フォルダに 2 つの Word ができます。解像度不足や見つからない写真があれば、その場で一覧が出ます

原稿は、区分を切り替えたとき・Word を作るとき・閉じるときに自動で保存されます。

## 直したものを戻す

原稿欄の上の **「↩ 一つ手前に戻す」** で戻せます（`Ctrl+Z` ／ `⌘Z` でも同じ）。

- **「まとめて直す」「数字をそろえる」のように一度にたくさん変わった操作も、1 回で戻ります**
  （消す・入れるをひとまとまりにしてあるため。そうしないと 2 回押す必要があります）
- 戻したあとは `Ctrl+Y` ／ `⌘⇧Z` でやり直せます
- **区分を切り替えると、それより前には戻せなくなります**（別の区分の履歴が混ざらないように）
- 戻した内容はすぐファイルにも保存されます

## 校正する

区分を開いて **「校正する」** を押すと、指摘の一覧が別の窓に出ます。

| 種類 | 例 |
|---|---|
| 表記ルール | 等 → など、出来る → できる、ひとつ → 一つ |
| 重言・二重敬語 | まず最初に、お伺いさせていただく |
| 機種依存文字 | ①㈱№ → 印刷所で化けるので (1) などに |
| 誤字 | 週知 → 周知、絶対絶命 → 絶体絶命 |
| 同音異義語 | 追求／追及／追究、保障／保証／補償 の確認（43 組） |
| 文法 | ら抜き・い抜き・さ入れ、助詞の重複 |
| 記号・句読点 | 括弧の対応、半角カナ |
| 読みやすさ | 1 文が長い、「が、」の多用、「の」の連続 |
| ルビ | 浚渫・暗渠などの難読語（59 語） |
| 固有名詞 | 山崎 → 山﨑 のような字形の取り違え（日高村の地名・議員・施設など 109 語） |

- 指摘を押すと、**原稿のその場所が選ばれます**
- 重要度は **要修正（赤）／確認（橙）／参考（青）**
- **「自動で直せる○件をまとめて直す」** で一括修正（何を直すか確認の画面が出ます）
- 「まず最初に → まず／最初に」のように**どちらか選ぶものは自動修正しません**

辞書は `proof_data/` の 4 つの JSON です。**コードを直さなくても、この JSON を直せば
指摘の内容を変えられます**（議員の改選、新しい施設名など）。

### 表紙の写真は「表紙」を選ぶ

表紙の大きな写真には、大きさに **「表紙」** を選びます。**A4 一面（紙の端まで）** という指示になり、
原稿 Word には次の赤字が入ります。

```
【写真1】表紙写真.jpg（A4 一面・紙の端まで／塗り足し 3mm を付けてください）　説明: …
```

- Word には**余白の内側いっぱい（幅 170mm）**で貼ります。紙の端までは Word で表せないので、
  実物の大きさは赤字の指示で伝えます
- **塗り足し**（紙の端まで色を出すため、仕上がりより少し大きく作ること）が要るので、その旨も入れてあります
- 解像度の判定は **210mm 基準**です。A4 一面に耐えるには**横 2,900 ピクセル**ほど必要なので、
  足りなければ赤字で知らせます
- 表紙以外の区分で「表紙」を選ぶと**警告が出ます**（本文は縦書き 5 段なので段をはみ出すため）

## 選んだところが何字かを見る

原稿欄で**文字をドラッグして選ぶ**と、区分名の右にその部分の量が出ます。

```
一般質問   選んだ範囲 21 字（組版 20 字 ＝ 1.5 行）
```

- **選んでいないときは、その区分ぜんぶ**の量が出ます
- 「組版」は**半角を 0.5 文字として数えたもの**です（「令和10年度…」は見たまま 21 字でも、紙面では 20 字ぶんの幅）
- 紙面の大きさに合わせて、**行 → 段 → ページ**と単位が変わります
  （1 段に収まるうちは「○行」、1 ページに収まるうちは「○段（○行）」、それ以上は「○ページ」）

「この記事は何段になるか」を確かめながら書けるので、枠に入るかの見当が付きます。

## 分量を見る（文字数チェック）

下の **「分量を見る」** を押すと、区分ごとの字数と、全体で何ページになるかが出ます。

```
第204号　全体で およそ 10 ページ（偶数）
紙面の決まり: 縦書き 5 段／1 行 13 字／1 段 33 行 ＝ 1 ページ 2145 字
```

- 字数は **組版の幅**で数えます（半角は 0.5 文字。「12日」は 2 文字ぶん、「１２日」は 3 文字ぶん）
- 写真が本文を押しのけるぶんも字数に足して計算します
- **奇数ページのときは赤字で知らせます**（紙は表と裏があるので、最後の 1 ページが白紙になります）

目安です。実際のページ数は印刷所の組み方で前後します。

## ローカル LLM を使う（任意・入れなくても動きます）

ルールベースの校正は「規則に当てはまるもの」しか見つけられません。
**脱字**や**「以外／意外」の取り違え**のような文脈で決まる誤りは、
小さな言語モデル（LLM）に見てもらえます。校正の窓の **「AI 校正も使う」** です。

**入れていなければボタンを押しても「使えません」と出るだけで、ほかの機能はふつうに動きます。**

### 原稿は外に出ません

つなぐ先は **127.0.0.1（このパソコン自身）だけ**です。ほかのパソコンやインターネット上の
サービスは、設定でも指定できないようにしてあります（`llm.py` の `_check_host`）。

### ネットにつながらないパソコンへの入れ方

インターネットにつながるパソコンで用意して、USB で持ち込みます。

1. **つながるパソコンで**
   - Ollama（<https://ollama.com>）のインストーラをダウンロード
   - Ollama を入れて、コマンドプロンプトで `ollama pull qwen2.5:7b`
   - モデルの入っているフォルダを丸ごと USB へコピー
     （Windows: `C:\Users\<利用者名>\.ollama\models`）
2. **役場のパソコンで**
   - インストーラを実行して Ollama を入れる
   - USB の `models` フォルダを `C:\Users\<利用者名>\.ollama\` の下に置く
   - コマンドプロンプトで `ollama list` と打ち、モデル名が出れば準備完了

### 選ぶモデル — 実際に試した結果

メモリ 8GB の Mac で、第201号の刷り上がった原稿 1,200 字を使って測りました。

| モデル | 大きさ | 刷り上がった原稿への**誤検出** | わざと入れた誤りの検出 | 速さ |
|---|---|---|---|---|
| `qwen2.5:3b` | 1.9GB | **3 件**（すべて的外れ） | 0/3 | 23 字/秒 |
| `qwen2.5:7b` | 4.7GB | **0〜2 件** | 1/3 | 19 字/秒 |

**`qwen2.5:7b` を使ってください。** 3b は「武政義幸様 → 武政義幸様」のように直っていない
指摘や、固有名詞の書き換えを返してきて、実用になりませんでした。
入っているモデルから自動で良いほうを選びます（`llm.py` の `PREFERRED`）。

### 承知しておいてほしいこと（実測にもとづく）

- **遅いです。** 19 字/秒なので、**1 万字の号だと 9 分ほど**かかります（メモリ 8GB・GPU なしの Mac で実測）
- **見逃します。** わざと入れた 3 つの誤りのうち、拾えたのは 1 つ（「説明ました → 説明しました」）でした。
  「ためにが重要」のような助詞の誤りは見逃しました。**AI を通したから大丈夫、とは考えないでください**
- **たまに外れます。** 同じ原稿でも実行のたびに結果が少し変わります。誤りではない箇所に
  「より丁寧な言い回し」を提案してくることがあります
- そのため AI の指摘は **「参考（青）」** として出し、**まとめて自動修正の対象にはしません**
- **必須ではありません。** ふつうの校正と文字数チェックだけでも十分に使えます。
  AI 校正は「ルールでは拾えない誤字が、ときどき見つかるかもしれない」程度の補助と考えてください

## 数字の全角・半角

縦書きでは半角の数字が横に寝るため、従来の `.doc`（4 号分）で使われていた規則に自動でそろえます。

| 規則 | 例 |
|---|---|
| 1 桁は全角 | ４人、３月、第８号 |
| 2 桁以上は半角 | 第46回、国道33号、131チーム、2025年 |
| 「－」でつないだ番号はそのまま | 〒７８１－２１９４、℡０８８９－２４－７７７７、本郷６１－１ |
| 表紙・【写真】行は触らない | 第２０４号（題字）、写真のファイル名 |

適用されるのは「原稿ファイルを取り込む」とき、「数字をそろえる」ボタンを押したとき、
「Word を作る」とき（原稿ファイル自体は書き換えません）の 3 か所です。
さらに原稿 Word では、2〜3 桁の半角数字に Word の **縦中横**（数字を立てて 1 文字分に入れる）を掛けるので、
縦書きでも「第46回」「131チーム」が横に寝ません（4 桁以上はそのままです）。
止めたいときは `core.py` の `NUMBERS_TATEGAKI = False` にします。

## 出力される Word

| ファイル | 中身 |
|---|---|
| `第○号_原稿.docx` | 従来の `.doc` と同じ紙面。**表紙は横書き 1 段、本文は縦書き 5 段**（A4、余白 上15・下12・左右15mm、段間 6mm、ＭＳ明朝 10.5pt）。区分ごとに改ページ。【写真】行の場所に **赤い指示文（番号・ファイル名・大きさ・説明）と縮小した写真** が入る（写真は 1 段の高さに収まるよう縮めて貼る。印刷所への大きさの指示は赤字のとおり） |
| `第○号_写真配置指示.docx` | 横書きの写真一覧表（番号・縮小画像・ファイル名・区分・大きさ・説明・解像度の注意）。使っていない写真と「別添」フォルダの中身も末尾に出る |

写真は 350dpi で刷ったときに指定の幅に足りるかを確かめ、足りなければ赤字で「元データをもらってください」と出ます。
（メールで縮小された写真は印刷に使えないことが多いためです）

## 変えたくなったら

- 号の種類ごとの区分の並び → `core.py` の `TEMPLATES`、区分のヒント → `HINTS`
- 校正の辞書（表記ルール・同音異義語・固有名詞・ルビ） → `proof_data/` の JSON
- AI 校正のモデル・待ち時間・指示文 → `llm.py` の `CHUNK_CHARS`・`TIMEOUT_SEC`・`PROMPT`
- 写真の大きさの種類・幅 → `core.py` の `SIZES`
- 表紙の雛形の文面 → `core.py` の `COVER_TEMPLATE`
- 原稿 Word の本文を横書きにする → `core.py` の `TATEGAKI = False`
- 段数・余白・段間・行送り → `core.py` の `DANSU`・`MARGIN_MM`・`DAN_SPACE_MM`・`LINE_SPACING`
- 数字の自動変換を止める／対象外の区分を増やす → `core.py` の `NUMBERS_TATEGAKI`・`NUMBERS_SKIP_KUBUN`
- Word の余白・フォント → `core.py` の `_setup_page`
