# 議会だより 前年同月号 差し込みツール 設計書

版 1.0／2026-09-28

この文書は「このツールが何を、どういう考えで、どう動かしているか」を、次の担当者や
手直しする人が読めるようにまとめたものです。使い方だけを知りたい場合は `README.md` を
読んでください。

---

## 1. 目的と割り切り

### なぜ 3 つ目のツールなのか

議会だよりを作る道具は、これで 3 つ目です。順に作った理由は次のとおりです。

| ツール | 考え方 | 行き詰まったところ |
|---|---|---|
| `gikai_editor` | 多機能。原稿を解析して紙面を組む | 機能が増えすぎ、引き継ぎづらい |
| `gikai_simple` | 推測しない。文字だけの原稿と写真の指示を作り、**組版は印刷所に任せる** | 印刷所に渡す前提。手元で紙面の形を確かめられない |
| **`gikai_template`（本書）** | **前年の同じ月の号を様式にして、文字だけ入れ替える** | — |

`gikai_simple` と `gikai_editor` の出力が「元の紙面のようにならない」という声が出発点です。
原因を調べると、実物の議会だよりは**文字枠を手で重ねて作られていました**。枠の位置・大きさ・
書式が 1 つずつ手作業で決めてあるため、紙面を一から組み立てる方式では同じ見た目になりません。

そこで発想を変え、**前年の紙面そのものを様式として使い、中の文字だけを入れ替える**ことにしました。
書式・枠の位置・表紙・裏表紙は前年のまま残るので、見た目は必ず前年と同じになります。

### 前年の「同じ月」を使う理由

日高村議会だよりは年 4 回（4・7・10・1 月）発行で、月ごとに載せるものが決まっています。

| 今年作る号 | 様式（前年の号） | その月に載るもの |
|---|---|---|
| 4月号 | 第198号 | 3月定例会・当初予算・注目する事業 |
| 7月号 | 第199号 | 6月定例会 |
| 10月号 | 第200号 | 9月定例会・決算・議員行政視察研修報告 |
| 1月号 | 第201号 | 12月定例会・特集（新年の抱負） |

直前の号ではなく **1 年前の同じ月の号**を使うのは、構成がいちばん近いからです。
発行が済んだらその号を様式に登録し直すと、翌年はそれが様式になります。

### やらないこと（意図的に外したもの）

| やらないこと | 理由 |
|---|---|
| 紙面を一から組み立てる | それが `gikai_simple`／`gikai_editor` で、同じ見た目にならなかった |
| 前年の様式そのものを書き換える | 様式は資産。号フォルダに写した複製だけを触る |
| 写真を Word に貼る | 実物も写真は入っておらず、空行で場所を空けて印刷所が入れている。同じにする |
| 行数を正確に組む | 行数は**見積もり**。最後は人が Word で整える前提 |
| 追加の部品（python-docx など）を入れる | 役場のパソコンはインターネットにつながらない。標準ライブラリだけで書く |

## 2. 様式の作りと、そこから決まったこと

第198〜201号の `.docx` を解析して分かったこと（2026-09-25）が、設計のほぼすべてを決めています。

| 分かったこと | 設計への影響 |
|---|---|
| A4、余白 上15・下12・左右15mm。**表紙は横書き 1 段、本文は縦書き 5 段** | 区間（セクション）ごとに寸法を読む（`Geometry`） |
| **改ページが 1 つも無い。** ページの区切りは空行の数で手作業で合わせてある | 記事の長さが変わると以降が全部ずれる → **空行での位置合わせ**が要る（§6） |
| 見出し・質問題・写真の説明文・囲み記事は**文字枠**。見出しには 1 升の表もある | 欄は「本文の段落」「表の升目」「文字枠」の 3 種類 |
| 文字枠はすべて**段落につなぎ留めてある**（ページに固定した枠は無い） | 本文が伸び縮みすると枠も一緒に動く。だから位置合わせが効く |
| 写真は文書に入っておらず、本文の空行で場所を空けてある | 写真は扱わない。組み直しでは赤字で場所を示す |
| 本文は 11pt、1 段の 1 行は 12 字 | 行数の見積もりの基準 |

**この「改ページが無い」という 1 点が、このツールの設計の中心です。**
記事を 1 行長くすると、以降の記事と枠が 1 行ぶん食い違います。これを防ぐしくみ（§6）が本体です。

## 3. 全体の流れ

```
 前年の号（.docx）
      │  ① 様式を登録（app.pyw → 様式/4月号.docx …）
      ▼
 ┌─────────────── 号フォルダ（第205号/）───────────────┐
 │  様式.docx     ← 登録した様式を号ごとに写す（あとで差し替えても、この号は変わらない）
 │  号情報.json   ← 号数・発行日・月号
 │  差し込み.json ← 欄ごとの内容・組み替えの記録・原稿の指定
 │  別添/         ← 賛否表の Excel
 │  出力/         ← できあがった Word
 └──────────────────────────────────────────────────┘
      │  ② 様式を読み取り、差し込み欄に分ける（Template._scan → Slot ×195）
      ▼
 画面（app.pyw）で欄ごとに今年の原稿を書く／取り込む／組み替える
      │  ③ Word を作る（Issue.build）
      ▼
  ┌── flow.py ──┐ 原稿を選んだ区分は、様式の部品で組み直す（先に実行）
  └─────────────┘
  ┌── core.fill ─┐ 残りの欄は文字を入れ替える。長さの差は空行で吸収
  └──────────────┘
      ▼
 出力/第205号.docx ＋ 気になるところの一覧（Report）
```

**組み直し（flow）を差し込み（fill）より先に行う**のは、前年の長さを「手を加える前の様式」で
測る必要があるためです（`Issue.build`）。

## 4. データの持ち方

### 4.1 号フォルダ（1 号 = 1 フォルダ）

```
第205号/
  号情報.json     号数・発行日・月号・賛否表の Excel のパス
  様式.docx       号を作ったときに写した前年の号
  差し込み.json   欄ごとの内容・組み替えの記録・原稿の指定
  別添/           賛否表の Excel など、印刷所に渡すもの
  出力/           第205号.docx
```

フォルダごとコピーすれば別のパソコンへ引き継げます。

**様式を号フォルダに写すのが要点**です。あとで「様式を登録」し直しても、すでに作った号は
写した様式を見続けるので、欄の ID がずれて原稿が迷子になることがありません。

### 4.2 `差し込み.json` の中身

```json
{
  "version": 1,
  "slots": { "B12": {"mode": "new", "text": "今年の原稿…"} },
  "ops":    [ {"op": "split", "id": "B12", "at": 3, "new": "B12/1"} ],
  "kinds":  { "B30": "見出し" },
  "flows":  { "一般質問": {"source": "…/05_一般質問.txt", "kinds": {…}} }
}
```

| 鍵 | 何を持つか |
|---|---|
| `slots` | 欄ごとの状態と文章。**前年のまま（`keep`）で文章も無い欄は保存しない**ので、195 欄あってもファイルは小さい |
| `ops` | 欄の組み替え（複製・分ける・つなげる・枠を消す）を**やった順に**記録 |
| `kinds` | 人が選び直した欄の種類 |
| `flows` | 区分ごとの原稿ファイルと、人が直した行の種類 |

**`ops` を順番に持つのが大事です。** 様式を開くたびに前年の号から組み替えをやり直すので
（`Issue.load_template`）、「分けた欄をさらに複製する」のような重なった操作も再現できます。
前年の号そのものは決して書き換えません。

### 4.3 欄（`Slot`）の状態

| 印 | 状態（`mode`） | Word ではどうなるか |
|---|---|---|
| ✎ | `new` 今年の原稿 | 書いた文に入れ替わる |
| ・ | `keep` 前年のまま（はじめはすべてこれ） | 前年の文のまま、**黄色の蛍光ペン**の印が付く |
| ＝ | `same` 毎号同じ | 前年の文のまま、印なし（発行元・再生紙の断り書きなど） |
| ✕ | `empty` 空にする | 文を消す。**本文は空行で埋めて以降の位置を保つ** |
| ▦ | `table` 賛否表 | Excel の賛否表を枠の中に入れる |

はじめをすべて「前年のまま＋黄色の印」にしているのは、**直し忘れを紙の上で見つけられるように**
するためです。刷る前に黄色が残っていないか見れば、抜けが分かります。

## 5. 様式の読み取り（`core.Template`）

### 5.1 欄に分ける（`_scan`）

文書を頭から 1 回だけ読み、紙面の順に欄を並べます。第201号で 195 欄になります。

| 入れ物 | 欄の種類 | 区切り方 |
|---|---|---|
| 本文の段落 | `body` | **空行で区切る**。空行と空行のあいだが 1 欄 |
| 表の升目 | `cell` | 升目ごと |
| 文字枠 | `box` | 枠ごと（VML の `v:shape`／`wps:wsp` 両方を拾う） |

同時に、18pt 以上の見出しが出てくるたびに「束ね名（`group`）」を切り替えます。画面の左の
一覧を区分ごとにまとめて見せるためです。

### 5.2 種類の見分け方（`Slot.kind_label`）

読み取った欄が何かは、**字の大きさと行の形**で見分けます。

| 種類 | 条件 |
|---|---|
| 名前（1字ずつ） | 3 行以上あり、どの行も 1〜2 字（`_looks_like_name_lines`） |
| 見出し | 13pt 以上で 1 行 |
| 本文 | それ以外 |

「名前（1字ずつ）」は、縦書きの紙面で名前を**横に並べる**ための組み方です。実物では
`　長／　村／郎／太／田／山` のように 1 字ずつの行になっています。人は「山田太郎　村長」と
1 行で書き、ツールが組み直します（`_name_to_lines`）。

### 5.3 読み取りを人が直せるようにした理由

見分けは字の大きさに頼っているので、前年の号の作り方しだいで外れます。
そこで**人が直せる 4 つの操作**を用意しました（`ops` に記録され、開くたびに再現されます）。

| 操作 | 使う場面 |
|---|---|
| 種類を選び直す（`set_kind`） | 見出しなのに「本文」と出ている |
| 分ける（`split`） | 見出しと本文が 1 欄にくっついている |
| つなげる（`merge`） | 1 つの記事が写真の空行で 2 欄に割れている |
| 複製（`duplicate`）／枠を消す（`remove_box`） | 前年に無い記事を足す／要らない枠を消す |

**文字枠・表の升目・本文のあいだで種類は変えられません。** Word の中で入れ物そのものが
違うためです（`KIND_CHOICES` は本文の流れの中の段落だけを対象にしています）。

## 6. 紙面がずれないしくみ（`_compensate`）★中心

**このツールでいちばん重要な部分です。**

前年の号には改ページが無く、ページの区切りは空行の数で合わせてあります。記事を書き換えて
長さが変わると、以降の記事も枠もすべてずれます。

そこで、**記事が前年より何行伸び縮みしたかを数え、すぐ後ろの空行を同じ行数だけ減らす（足す）**
ことで、以降の位置を元に戻します。

```
前年:  記事A（10行）  空行×4   記事B …
今年:  記事A（13行）  空行×1   記事B …   ← 3 行伸びたぶん、空行を 3 行減らす
                     ↑ここで吸収するので、記事B 以降は前年と同じ位置
```

行数は紙面から計算します（`Geometry.chars_per_line`）。1 段の長さを字の大きさで割った値で、
本文 11pt なら 1 行 12 字。第201号の画面で数えた値と一致することを確かめてあります。

### 空行を減らすときの決まり

- **枠をつなぎ留めている空行は消さない**（`_has_anchor`）。消すと文字枠ごと消えます
- **区間の終わりの空行（`sectPr` を持つもの）も消さない**
- 全部が消せる空行でも、**先頭の 1 行は残す**。記事と記事のあいだの空きが無くなるのを防ぐため
- 足りなければ「どの記事が約何行あふれたか」を報告する（`Report.overflow_body`）

### 文字枠のはみ出し（`_box_overflow`）

文字枠は伸び縮みしないので、入りきらないかどうかを枠の寸法から見積もって知らせます。
枠の幅・高さ（mm）と字の大きさから「1 行に何字・何行入るか」を出し、必要な行数と比べます。

**どちらも目安です。** 行数は見積もりなので、最後は Word で確かめる前提にしています。

## 7. 原稿を欄へ振り分ける（`assign_blocks`）

議員から届く Word には見出しと本文がいくつも続けて書かれています。1 欄ずつ写すのは手間なので、
**まとまりに分けて（`split_manuscript`）、欄へまとめて振り分け**られるようにしました。

### 前から順に詰めるのをやめた理由

はじめは前から順に詰めていましたが、**1 か所ずれると後ろが全部ずれます**。
第201号の行政報告で試すと 26 のまとまりのうち 8 しか合いませんでした。

そこで、**全体でいちばん手間の少ない組み合わせを動的計画法で探す**ことにしました。

| 手 | 手間 | いつ使うか |
|---|---|---|
| 欄を飛ばす | `COST_SKIP_SLOT` 1.0 | 原稿に対応するものが無い欄 |
| 写真の説明文・名前の欄を飛ばす | `COST_SKIP_MINOR` 0.1 | 原稿に無いのがふつうなので安くする |
| 前の本文につなげる | `COST_APPEND` 0.6 | 原稿のほうが細かく分かれている |
| どの欄にも入れない | `COST_DROP` 3.0 | 合う欄が無い（後ろをずらさないため） |
| 前年と同じ言葉で始まる | `BONUS_SAME` −0.8 | 毎年ある「防災訓練」などを目印にする |

これで 26 のうち 22 が正しい欄に入りました。外れた 4 つは様式の読み取りのくっつきが原因で、
「分ける」で直せます。

**案でしかないので、必ず確認の画面（`DistributeDialog`）で人が確かめてから反映します。**

## 8. 原稿から組み直す（`flow.py`）★中心

### なぜ差し込みでは足りない区分があるのか

行政報告・審議したこと・委員会報告・一般質問・特集は、**記事の数や議員の人数が毎回違います**。
前年の欄に差し込む方式では数が合いません。

そこで、これらは**前年の号から「部品」を取り出し、今年の原稿に合わせて必要な数だけ並べ直します**。

| 部品 | 様式のどこから取るか | 組み直すとき |
|---|---|---|
| 議員の最初の題 | 題の表・文字枠の中の大きな字（18〜28pt） | **罫線で囲んだ段落**にして本文の流れに置く |
| 名前 | 1 字ずつの行（「議員」まで 1 字ずつそろった人を見本にする） | 後ろの字から 1 字ずつの行で組む |
| 2 問目からの題 | 14pt の段落 | 同じ書式で。前後に空行 1 行 |
| 質問・答弁・本文 | 「質問」「答弁」で始まる段落・本文の段落 | 頭の言葉だけ太字などの書式も写す |
| 写真 | （前年の空行） | 赤字で場所を示し、写真の幅ぶんの空行を空ける |

### 題を「枠のまま」使わなかった理由

前年の題の表や文字枠をそのまま使うと、次の不具合が起きることを第198・201号で確かめました。

- 前年の題の長さに合わせて寸法が決めてあるので、今年の題が長いと**はみ出す**
- 本文の外に浮かせてあるので、**本文と重なる／段の境目で切れる**

そこで**罫線で囲んだ段落**にしました。段落なら Word が本文と同じように段・ページを送ります。
題と名前には「次の段落と同じ段に置く」（`keepNext`）を付けているので、**題だけが段の最後に
取り残されることもありません**。

### 後ろの記事がずれないしくみ

様式の本文は表紙のあとから 1 本の流れで、文字枠はすべて段落につなぎ留めてあります。
そこで組み直した長さに合わせて空行を足し、**前年との差を「ちょうど何ページ分」にそろえます**。

- 前年より短くて 1 ページ以上余るときは、空白のページを作らず**ページごと詰める**
- 前年より長いときは、後ろの記事を**ページ単位で送る**

1 段 = 11pt の行で 36 行（`TIER_LINES`）、1 ページ = 5 段で 180 行。Mac の Word で第201号を
測った値です。印刷は 4 ページ単位のことが多いので、ページ数が変わったら報告します。

### 区分ごとの違い

| 区分 | 組み直し方 | 特記 |
|---|---|---|
| 行政報告・委員会報告 | 見出し＋本文の並びとして組む | 頭（「行政報告（要旨）」の表と村長名）は組み直さず差し込む |
| 審議したこと | 区分（人事・条例…）を**罫線で囲んだ段落**に | 枠のままだと重なり・切れが起きるため |
| 一般質問 | 議員ごとに題・名前・質問・答弁を組む | 人数は数えて「○氏が立つ」を入れ直す |
| 特集 | 組み直さず、**前年の人ごとの枠に今年の人を入れる** | テーマも組み方も毎年違うため |

特集だけ方式が違うのは、第198号（二十歳のつどい）・第200号（金婚）・第201号（新年の抱負）と
**毎年まったく違う組み方**をしているためです。人ごとの枠で組まれていない号（第198・199号）では
「枠に入れられない」と知らせて前年のまま残します。

### 区分の終わりの見分け方

大見出しの字が読み取れない号があるため、次の 3 つを併用しています。

- 次の大見出し
- 「○月議会では」の枠（第198・199号の「審議したこと」には大きな見出しが無い）
- 「◎」で始まる議案の行

## 9. 賛否一覧表（`xlsx_vote.py` / `vote_docx.py`）

事務局の Excel を読み、「別添１：…賛否」の枠の中に Word の表として入れます。

- **行・列の位置を決め打ちしない。** 「議決結果」の見出しを手がかりに、議員名・区分・件名・
  ○●・結果を読み取ります（`parse_vote_table`）。事務局が行を足しても動くようにするためです
- Excel のふりがなは混ぜません
- 表は**横書きの枠の中**に入れるので、Excel と同じ向き（議案が上から下、議員名が左から右）
- 枠は紙面の幅いっぱいに広げ、**ページの下端**にそろえます（前年の号で表の場所として空けてある段）
- 1 段（約 48mm）より高いときは、上の段と重なることを知らせます
- 古い `.xls` は読めません（Excel で `.xlsx` に保存し直してもらう）

`openpyxl` を使わず標準ライブラリだけで読んでいるのは、追加の部品を入れないためです。

## 10. 画面（`app.pyw`）

Tkinter の 1 枚窓。左に欄の一覧（区分ごとに束ねた木）、右上に前年の文章（見本）、
右下に今年の原稿を書く欄という配置です。

| 補助の窓 | 役割 |
|---|---|
| `NewIssueDialog` | 新しい号を作る |
| `RegisterDialog` | 4月号〜1月号それぞれに前年の号を登録する |
| `DistributeDialog` | 原稿の振り分け案を人が確かめる（§7） |
| `FlowDialog` | 組み直しの行の種類を人が確かめる（§8） |
| `ReportWindow` | Word を作ったあとの「気になるところ」一覧 |

画面が覚えるのは `設定.json` の**最後に開いた号のフォルダだけ**です。原稿はすべて号フォルダに
入るので、パソコンを変えてもフォルダを持っていけば続きができます。

## 11. Word の XML を素手で扱うときの落とし穴

追加の部品を入れないため、`.docx` を標準ライブラリの `ElementTree` で直接扱っています。
そこで踏んだ落とし穴を残しておきます。

| 落とし穴 | 対処 |
|---|---|
| `ElementTree` は**使っていない名前空間の宣言を落とす**。Word は `mc:Ignorable` に書かれた接頭辞の宣言が無いと「壊れている」と判断する | 保存するとき、**ルート要素の開始タグだけ元のものに戻す**（`_serialize`） |
| `w:pPr` / `w:rPr` の中の要素は**順番が決まっている**。違う順で入れると Word が開けない | `PPR_ORDER` / `RPR_ORDER` の順に挿入する（`_insert_ordered`） |
| 段落や図形の ID が重複すると壊れる | 複製したら ID を振り直す（`_strip_ids`） |
| 縦中横（`w:eastAsianLayout`）には一意の ID が要る | `_EA_ID` で通し番号を振る |
| 文字枠は VML（`v:shape`）と DrawingML（`wps:wsp`）の 2 通りある | 両方を拾う（`_find_boxes`） |

## 13. 動作環境と既知の制約

### 動作環境

- **Python 3.9 以降。追加の部品は要りません**（標準ライブラリだけ）
- Windows 10 で `起動.bat` から起動
- インターネットには何も送りません

### 確かめたこと

Mac の Word で第198〜201号を様式にして、次を目で見て確かめています。

- 作った Word が壊れずに開く（4 号すべて、5 区分すべて）
- 本文の入れ替え・縦中横・1 字ずつの名前・表紙の号数と発行日・黄色の印・賛否表の見た目
- 行政報告／委員会報告／一般質問の組み直しの見た目（第198・200・201号）

### まだ確かめていないこと

- 本物の一般質問の原稿での読み取りの当たり具合
- **Windows の Word での見た目**（Mac とは字の幅が違い、Mac では前年の号そのものでも
  特集の見出しの枠がページをまたいで見える）
- `.doc` を Windows の Word で自動変換する機能（`convert_doc_with_word`。PowerShell 経由）
- `起動.bat` の動作

**役場のパソコンで一度通してください。**

### 制約

| 制約 | 理由 |
|---|---|
| 行数は見積もり | 改ページが無い紙面での計算値。最後は Word で整える |
| 古い `.xls` の賛否表は読めない | `.xlsx` だけ対応（`.xlsx` に保存し直す） |
| 文字枠・升目・本文のあいだで種類を変えられない | Word の中で入れ物が違う |
| 特集は人ごとの枠がある号でしか組めない | 第198・199号はその組み方ではない |

## 15. 3 つのツールの関係

| | `gikai_simple` | `gikai_template`（本書） | `gikai_editor` |
|---|---|---|---|
| 作るもの | 文字だけの原稿 Word ＋ 写真配置指示書 | **前年の紙面と同じ形の Word** | 紙面を組んだ Word |
| 組版 | 印刷所 | ほぼ済んだ状態で渡す | ツール |
| 前年の号 | 要らない | **必要** | 要らない |
| 追加の部品 | python-docx・Pillow | **不要** | 多い |

3 つは競合ではなく、**役割が違います**。

- 原稿を集めて整える段階は `gikai_simple` が向いています（区分ごとに書き、写真の指示を付ける）
- その原稿をそのまま `gikai_template` の「原稿から組み直す」に渡せます
  （`02_行政報告.txt`・`05_一般質問.txt` などをそのまま選べる）
- 【写真】行の書き方（`【写真】ファイル名｜大きさ｜説明`）は **2 つのツールで同じ**です
- 写真の大きさも大（80mm）・中（55）・小（38）・顔（26）は同じですが、
  **「表紙」だけ食い違っています**（`gikai_simple` は 210mm ＝ A4 一面、本ツールは 180mm）。
  `flow.py` の `PHOTO_MM` のコメントは「`gikai_simple` と同じ幅」と書いていますが、
  表紙については正しくありません。組み直し（一般質問・行政報告）に表紙の写真は出てこないので
  実害は出ていませんが、直すなら 210 にそろえてください

`doc97.py`（旧 `.doc` から文字を取り出す）は `gikai_simple` から複製したものです。
どちらのツールも単体で動くことを優先し、あえて共有していません。
