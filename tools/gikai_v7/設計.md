# V7 設計

## V6から変えたこと

- 原稿の部品分け・種類変更・手動移動を通常画面から外し、区分ごとの入力欄へ置き換えた。
- `items.py` が入力を V6 互換の印付き原稿へ変換する。既存の `ingest`、`compose`、`templates`、`docx_out` は引き続き紙面作成に使う。
- `app.pyw` を15手順のナビにした。説明文は `guide.py` に分け、運用に合わせて文章だけ直せる。
- 画面の保存、ページ再構成、写真、出力はすべて `Edition` 経由にした。
- 一般質問の人数と委員会報告の件数からページ割りを再作成する。行政報告・委員会報告・特集などは次ページ送りを自動設定する。
- `votes_xlsx.py` が標準ライブラリだけで `.xlsx` のひな形作成と読取を行う。賛否は画面で編集せず、Excelを唯一の元データにして食い違いを防ぐ。取込後は元を変更せず `賛否` に複製し、由来を `項目.json` に残す。
- 議案と賛否の手順は「審議したこと」の直前に置いた。先にExcelを取り込めば、件数と議案名を次の画面でそのまま確認・選択でき、初めての職員が二重入力しにくいため。
- `sources.py` がWord、メール本文、手書き入力後の確認用Wordを扱う。受取方法・受取日・議員確認と、名簿全員の受付状況を項目データに保持する。
- 写真は受取時に議員名・記事名・連番で複製する。既存の `placed_photos`、`compose` の占有領域、undo/redo、`docx_out.Picture` を維持し、画面だけをクリック・ドラッグ中心にした。
- 入力を `項目.json` に保存し、直前の内容を `項目_前回.json` に残す。Wordは毎回別の出力フォルダへ作る。

## 変えない部分

Wordで確認済みの行送り、枠寸法、見出し枠、縦書き拡張、縦中横、余白、5段×30行×12字、写真出力の仕組みは既存コードを使う。書体は一般質問の答弁本文だけMS明朝、それ以外の本文・問・答弁者名はMSゴシック11ptとする。
