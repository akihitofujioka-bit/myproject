# アプリをiPhoneから使えるようにする（GitHub Pages の有効化）

`apps/` の2つのアプリを公開し、iPhone から開けるようにするための操作手順。
**一度やれば、以後は変更を `main` に反映するだけで自動的に更新される。**

所要時間は5分ほど。GitHub の画面はパソコンでもスマートフォンでも操作できるが、
パソコンのブラウザのほうが分かりやすい。

---

## 手順1：変更を `main` に反映する（プルリクエストのマージ）【完了済み】

> この手順は 2026-09-03 に実施済み（PR #4・#5 をマージ）。
> 以降、同じ作業をするときのために手順を残しておく。

「プルリクエスト」は、作業した内容を本体（`main`）に取り込むための申請のこと。

1. ブラウザで https://github.com/akihitofujioka-bit/myproject を開く
2. 上部のタブから **「Pull requests」** を選ぶ
3. 一覧にある申請のタイトルを押して中身を開く
4. 画面を下にスクロールし、緑色の **「Merge pull request」** ボタンを押す
5. 続けて出てくる **「Confirm merge」** ボタンを押す
6. 「Pull request successfully merged and closed」と表示されれば完了

> 途中で「This branch has conflicts」と赤く出た場合は、自動で取り込めない食い違いがある。
> その場合は無理に進めず、状況を伝えてもらえれば解消する。

## 手順2：公開の仕組みを有効にする（**この操作だけは代行できません**）

ワークフローからの自動有効化も試したが、GitHub の権限の決まりにより拒否された
（`Create Pages site failed: Resource not accessible by integration`）。
Pages の有効化はリポジトリの管理者本人の操作が必要なため、ここだけはお願いしたい。

1. 同じリポジトリの画面で、上部のタブから **「Settings」**（歯車のアイコン）を選ぶ
   - タブが見当たらないときは、横に並んだタブの右端にある「…」の中にある
2. 左側のメニューを下にたどり、**「Pages」** を選ぶ
3. **「Build and deployment」** の下にある **「Source」** の選択肢を、
   `Deploy from a branch` から **`GitHub Actions`** に変える
4. 保存ボタンは無い。選んだ時点で設定される

### 手順2のあとに必ず行うこと

公開ワークフローは `apps/` 以下が変わったときにしか自動で動かない。
Pages を有効にしただけでは公開が始まらないので、**手で1回実行する**。

1. 上部のタブから **「Actions」** を選ぶ
2. 左の一覧から **「日常アプリを公開」** を選ぶ
3. 右側の **「Run workflow」** ボタン → 続けて緑の **「Run workflow」** を押す

---

## 手順3：公開されるのを待つ

1. 上部のタブから **「Actions」** を選ぶ
2. 「日常アプリを公開」という名前の実行が並んでいる。最新のものを押す
3. 緑色のチェックが付けば公開完了（1〜2分ほどかかる）
   - 黄色い丸は実行中、赤い×は失敗。赤くなった場合は、その画面をそのまま伝えてほしい

手順1のマージ直後に自動で実行されるが、動かない場合は
Actions の画面で「日常アプリを公開」→ 右上の **「Run workflow」** から手で実行できる。

---

## 手順4：iPhone のホーム画面に追加する

公開が終わると、次のURLで開けるようになる。

| | URL |
| --- | --- |
| 入口（両方へのリンク） | https://akihitofujioka-bit.github.io/myproject/ |
| 冷蔵庫 | https://akihitofujioka-bit.github.io/myproject/fridge/ |
| 書類トラッカー | https://akihitofujioka-bit.github.io/myproject/docs-tracker/ |

1. iPhone の **Safari** で上の入口のURLを開く（Chrome など他のブラウザではホーム画面に追加できない）
2. 画面下部の **共有ボタン**（四角から上向きの矢印）を押す
3. メニューを下にたどり **「ホーム画面に追加」** を選ぶ
4. 名前を確認して「追加」

冷蔵庫と書類トラッカーは別々に追加できる。それぞれのURLを開いて同じ操作をする。

### 初回に出る確認

- **カメラの使用**：バーコードを初めて読むときに聞かれる。「許可」を選ぶ
- 許可しそこねた場合は、iPhone の **設定 → Safari → カメラ** から変更できる

---

## うまくいかないときの確認

| 症状 | 確認すること |
| --- | --- |
| URLを開くと404 | 手順2の Source が `GitHub Actions` になっているか。手順3が緑になっているか |
| 「ホーム画面に追加」が出ない | Safari で開いているか（他のブラウザでは出ない） |
| カメラが起動しない | URLが `https://` で始まっているか。iPhone の 設定 → Safari → カメラ が「確認」または「許可」か |
| 直したはずの画面が古いまま | 一度アプリを閉じて開き直す（更新は次回の起動時に反映される） |

---

## 公開されるもの・されないもの

- **公開される**：`apps/` の中の画面（HTML・JavaScript・アイコン）だけ
- **公開されない**：入力した在庫や書類のデータ（各自の端末の中にのみ保存される）、
  `reports/` の日報・週報、`data/` の書き出しファイル、テスト、設定ファイル

このリポジトリはもともと公開設定のため、Pages を有効にしてもコードの公開範囲は変わらない。
