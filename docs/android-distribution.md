# 「ふたりのメッセージ」を Android アプリとして知り合いに渡す

配布用のアプリ一式は `mobile-messenger/` にある。

> **なぜ `mobile/` と別なのか。**
> `mobile/` は3つのアプリ（冷蔵庫・書類トラッカー・メッセージ）を1つに包んだ、自分用のアプリ。
> これをそのまま渡すと、**業務書類を扱う「書類・回覧の期限トラッカー」まで相手に渡ってしまう**。
> 配布用は `mobile-messenger/` として、メッセージアプリだけを含む別のアプリにしてある。

---

## 全体の流れ

| | やること | 所要 |
| --- | --- | --- |
| 1 | 中継サーバーを `https://` で用意する | 30分程度（初回だけ） |
| 2 | Android Studio を入れる | 1時間程度（初回だけ。ダウンロードが大きい） |
| 3 | 署名鍵を作る | 5分（初回だけ） |
| 4 | APK を作る | 数分 |
| 5 | 相手に APK と説明文を渡す | — |
| 6 | 相手の端末で導入し、招待コードを交換する | 10分 |

中継サーバーの用意は [`docs/messenger-setup.md`](messenger-setup.md) を参照。**これが無いとメッセージは届かない。**

## 2. Android Studio を入れる

<https://developer.android.com/studio> から入手する。**Mac（Apple Silicon を含む）・Windows・Linux のいずれでもよい。**
初回起動時のウィザードをそのまま進めると、必要な Android SDK が入る。

## 3. 署名鍵を作る（1回だけ）

配布する APK には署名が要る。次を1回だけ実行する。

```bash
cd mobile-messenger
keytool -genkeypair -v -keystore messenger-release.keystore \
  -alias messenger -keyalg RSA -keysize 4096 -validity 10000
```

暗証番号を2回、氏名や組織名を順に聞かれる。氏名・組織名は自由に決めてよい（アプリの画面には出ない）。

続いて `mobile-messenger/keystore.properties` を作り、次の4行を書く。

```properties
storeFile=messenger-release.keystore
storePassword=（上で決めた暗証番号）
keyAlias=messenger
keyPassword=（上で決めた暗証番号）
```

> **この鍵と暗証番号は必ず保管すること。**
> - **失うと、以後このアプリを更新できなくなる。** 相手は一度アンインストールして入れ直すことになる
> - **漏れると、他人があなたのアプリの「更新版」を偽造できる。** 相手の端末に偽物が入る恐れがある
>
> 鍵ファイル（`*.keystore`）と `keystore.properties` は、git 管理から外してある。
> パスワード管理ソフトや、施錠できる場所に控えを残すこと。

## 4. APK を作る

```bash
cd mobile-messenger
npm install        # 初回だけ
npm run apk
```

終わると、できあがった場所と**確認用の符号（SHA-256）**が表示される。

```
場所　: .../app/build/outputs/apk/release/app-release.apk
確認用の符号（SHA-256）: 1a2b 3c4d …
```

Android Studio の画面で作りたい場合は `npm run android` で開ける。

## 5. 相手に渡す

APK ファイルをメール添付・クラウド・USB などで渡す。あわせて**確認用の符号**も伝える。

相手が受け取ったファイルの符号が一致すれば、途中ですり替えられていないことを確認できる。
相手側の確認方法（パソコン）は `shasum -a 256 ファイル名`。

## 6. 相手の端末での導入

Google Play を通していないため、**「提供元不明のアプリ」の警告が出る**。次のように案内する。

1. 受け取った `.apk` ファイルをタップする
2. 「セキュリティ上の理由から…」と出たら「設定」を押す
3. 「この提供元のアプリを許可」をオンにして戻る
4. 「インストール」を押す
5. Play プロテクトの確認が出た場合は「詳細」→「インストールする」

導入後、[`docs/messenger-setup.md`](messenger-setup.md) の手順4のとおり招待コードを交換する。

## 相手に渡す説明文（そのままコピーして使えます）

> **「ふたりのメッセージ」について**
>
> 送るメッセージと写真は、あなたの端末と私の端末の中でだけ読める形にしてから送られます。
> 途中で預かるサーバーの管理者（私です）にも、通信を覗いた人にも、中身は読めません。
>
> **導入のしかた**
> 1. お送りした .apk ファイルをタップします
> 2. 「提供元不明のアプリ」という警告が出たら、「設定」→「この提供元のアプリを許可」をオンにして戻ります
> 3. 「インストール」を押します
> 4. アプリを開き、お名前と、お伝えするサーバーの住所（https://…）を入れます
> 5. 私がお送りする「招待コード」を貼り付け、出てきた「返信コード」を私に送り返してください
>
> **知っておいていただきたいこと**
> - この暗号のしくみは、標準的な方式で作っていますが、**専門機関の検査は受けていません**。
>   日常の連絡向けです。本当に重大な秘密のやりとりには「Signal」という専用アプリをお使いください
> - 本文と写真は読まれませんが、**「いつ、誰とやりとりしたか」の記録はサーバーに残ります**（私には見えます）
> - **端末を機種変更したり、アプリを削除すると、会話は元に戻せません**。
>   引き継ぐときは、アプリの設定にある「JSONで保存」を先に行ってください
> - このアプリでは**スクリーンショットが撮れません**。会話を残さないための仕様です
> - 「消えるメッセージ」を設定すると、決めた時間で両方の端末から自動的に消えます
>
> ご不明な点や、使うのをやめたいときは、いつでもお知らせください。

## このアプリの安全上の作り込み

配布にあたって、次のように設定してある（`node apps/tests/android-package.test.mjs` で検査している）。

| 項目 | 設定 | 理由 |
| --- | --- | --- |
| 求める権限 | **インターネット接続のみ** | カメラ・連絡先・位置情報・保存領域は一切求めない。写真の添付は端末標準の選択画面を使う |
| 自動バックアップ | **無効** | 秘密鍵と会話の履歴が Google のクラウドへ複製されるのを防ぐ |
| 端末間の移行 | **対象外** | 同じ理由。引き継ぎは利用者自身が「JSONで保存」で行う |
| 暗号化なしの通信 | **禁止** | `http://` を一切使わせない（通信の妨害や偽の応答を防ぐ） |
| スクリーンショット・画面録画 | **不可**（FLAG_SECURE） | 「消えるメッセージ」を意味のあるものにするため。アプリ切り替えの一覧にも会話が写らない |
| 動作確認用のビルド | **別アプリ扱い**（`.debug`） | 配布用と取り違えないようにするため |

> **スクリーンショットを撮れるようにしたい場合**は、
> `mobile-messenger/android/app/src/main/java/jp/myproject/messenger/MainActivity.java` の
> `FLAG_SECURE` の行を削除して作り直す。
> なお、**別のカメラで画面を直接撮影されることは、どの設定でも防げない。**

## 更新版を配るとき

1. `apps/messenger/` を直す
2. `mobile-messenger/android/app/build.gradle` の `versionCode` を1つ増やし、`versionName` を上げる
   （`versionCode` を上げないと、相手の端末で「更新」として認識されない）
3. `npm run apk` で作り直し、**同じ署名鍵で**署名されていることを確認する
4. 新しい APK を渡す。相手はそのままタップすれば上書き更新され、**会話の履歴は保持される**

## やってはいけないこと

- **動作確認用（debug）の APK を配らないこと。** 端末を USB でつなぐだけで、アプリの中の秘密鍵と履歴を取り出せてしまう。
  配布に使うのは `npm run apk` が作る release 版のみ
- **署名鍵をリポジトリに入れたり、人に渡したりしないこと**
- 相手の同意なくアプリを入れさせないこと。上の説明文を必ず添えること

## この環境で確認できていないこと

**APK の組み立て自体は未検証。** この開発環境からは Google のサーバーへ接続できず、Android SDK を取得できないため。

確認済みなのは次のところまで。

- Android プロジェクトの設定（権限・通信・バックアップ・署名・アイコン・撮影防止）が意図どおりであること
- **APK に入るのと同じ `www/` の中身**が、ブラウザ上で実際に動くこと
  （起動 → 招待コードの交換 → 文章と写真の送受信 → 消えるメッセージの設定まで）

つまり「材料は正しい」ところまでで、`gradlew assembleRelease` が通るかどうかは
Android Studio を入れた環境で最初に一度確かめる必要がある。
