# 件の読み取り機能の移植 設計書（計画 2-3）

作成 2026-10-13。壱師アプリと件 V2 の統合（案A＝件の機能を壱師へ移す）の計画 2-3。
2-1・2-2（予定アプリの新設・備蓄の削除）は `2026-10-09-schedule-app-design.md`。2-4（端末内 AI・AI 秘書・履歴）は別の設計書で扱う。

## 目的

件にあった次の 4 つの機能を壱師に移し、あわせて「思いついたことを書き留めて、予定ややることに移せる」メモを足す。

1. Word・Excel・PDF を読み込んで予定を取り出す
2. 通知に書かれた電話・メールを取り出す
3. 提案（予定の重複・移動時間不足・曜日と日付の食い違い）
4. やること候補（持参・提出・締切など）

## 決まったこと（利用者との確認 2026-10-13）

- 4 機能を 1 本の設計書・計画で作る
- ファイルの受け取りは **両方**: 予定アプリ内の「ファイルから読む」と、メール・「ファイル」App の **共有メニュー**
- 読み込むファイルの中身は **会議の開催通知（1 件）** と **行事予定表（複数件）**。名刺・連絡先の読み取りは対象外
- 電話・メールは **予定のメモに入れ、押すと電話・メールが起動** する
- やることは **書類・回覧トラッカーの中に作る**。名前を **「書類・やること」** に変える（短い名も「書類・やること」）
- やることの中に **自由メモのタブ** を作る。日付や「〜までに」があれば予定ややることへ移せる
- メモは **音声でも入力できる**。音声認識は **端末内だけ** で行う
- 提案は **確認画面** と **予定一覧の「気づいたこと」** の両方に出す
- 作り方は **案 1**: 文字の取り出しは iPhone 側（Swift）、予定の読み取りは Web 側（JavaScript）
- 壁打ち・ブレスト（端末内 AI との対話）は 2-4 で扱う。2-3 では AI を使わない

## 全体の流れ

1. 入り口
   - 「撮る」（今まで通り）
   - 予定アプリの「📁 ファイルから読む」
   - 共有メニューで「壱師」を選ぶ（壱師が開き、予定アプリへ移って読み取りに進む）
   - 書類・やることのメモ（文字か音声）→「予定に入れる」
2. iPhone 側の **DocumentReader** が Word・Excel・PDF から「文字の行」と「表（行×列）」を取り出して Web 側へ渡す。PDF に文字が無ければ端末内の文字認識（Vision）で読む
3. Web 側で中身を判定する
   - 表に日付の行が複数ある → `scheduletable.js` で予定の一覧を作り、複数件の確認画面へ
   - それ以外 → 今の `meeting.js` で 1 件として読み、1 件の確認画面へ
4. 確認画面で、見つかったものだけ「注意（提案）」「連絡先」「やること候補」を出す。登録はいつも人が確かめてから
5. 予定一覧の上に「気づいたこと」（これから 30 日の重なり・移動時間不足）

## 部品

| 部品 | 場所 | 役割 | 元にする件のコード |
|---|---|---|---|
| DocumentReader | `mobile/ios/App/App/DocumentReaderPlugin.swift` ほか | ファイル選択画面を開く、共有で届いたファイルを受け取る、文字と表を取り出す | `DocumentTextExtractor`・`ZipReader`・`OCRService` |
| 文字の取り出し（画面に依存しない部分） | `mobile/ios/App/App/DocumentText/`（新設） | docx・xlsx の ZIP と XML を読む、PDF の文字を読む。Mac 上でテストできるよう UIKit に依存させない | 同上 |
| 共有の受け取り設定 | `mobile/ios/App/App/Info.plist` | 書類の種類の登録（`CFBundleDocumentTypes`）で、共有メニューに「壱師」を出す。対象は docx・xlsx・pdf だけ | なし |
| SpeechMemo | `mobile/ios/App/App/SpeechMemoPlugin.swift` | マイクで話した内容を端末内だけで文字にする | なし |
| `scheduletable.js` | `apps/shared/` | 表から予定を複数取り出す | なし（新規） |
| `contacts.js` | `apps/shared/` | 電話・メール・URL を取り出す | `ContactDetector` |
| `suggest.js` | `apps/shared/` | 重複・移動時間不足・曜日の食い違いを見つける | `ScheduleHeuristics` |
| `todos.js` | `apps/shared/` | やること候補を見つけ、「書類・やること」に登録する | `ReminderService` |

- 連絡先・提案・やること候補を Web 側に置くのは、写真の読み取り（「撮る」）にも同じ部品を使え、パソコンでテストできるため
- Web 側の部品は今の `meeting.js` と同じ書き方（`(function (global) { … })`、通信なし、ブラウザなしでテストできる）にそろえる

### 各部品の決まり

**DocumentReader（Swift）**
- `pick()`: 「ファイル」App の選択画面を開く。選べるのは docx・xlsx・pdf だけ。結果は `{ name, kind: "docx"|"xlsx"|"pdf", lines: [文字列], tables: [[[セル]]], ocr: 真偽 }`
- `takeShared()`: 共有メニューから届いたファイルがあれば同じ形で返し、無ければ空を返す。届いたファイルのコピーは、読み終えたら消す
- docx: `word/document.xml` の段落を行に、表（`w:tbl`）を tables に入れる
- xlsx: `xl/sharedStrings.xml` と各シートを読み、シートごとに 1 つの表にする。日付のセル（シリアル値）は `YYYY-MM-DD` の文字に直す
- pdf: PDFKit でページの文字を読む。どのページにも文字が無ければ、ページを画像にして Vision で文字認識し、`ocr: true` を返す
- 読めないとき（パスワード付き・壊れている・古い .doc / .xls・空）は、理由を日本語で返す

**scheduletable.js**
- 表の見出し行から「日付」「時刻」「件名（行事名・内容）」「場所」の列を探す。見出しが無いときは、日付らしいセルの多い列を日付の列とみなす
- 日付が読めた行を 1 件の予定にする。年が書かれていなければ、今日以降で一番近い年にする
- 日付の行が 2 行以上ある表だけを「行事予定表」とみなす

**contacts.js**
- 電話番号（市外局番つき・携帯・内線の「内線 123」）、メールアドレス、URL を取り出す。重複を除き、出てきた順に並べる
- 予定のメモには「問い合わせ: 電話 0xx-xxx-xxxx / メール xxx@example.jp」の形で 1 行足す

**suggest.js**
- 重複: 同じ日に時間が重なる予定
- 移動時間不足: 場所が違う予定どうしの間が 15 分未満（件と同じ値）
- 曜日の食い違い: 通知に書かれた曜日と、日付の実際の曜日が違う
- 入力は予定の配列（壱師の予定と iPhone カレンダーの予定を同じ形にしたもの）。終日の予定は重複・移動時間の判定から外す
- 各指摘に「鍵」（種類＋相手の予定の識別子＋日時）を付ける。消した指摘は鍵で覚え、日時が変われば鍵も変わるので再び出る

**todos.js**
- 「持参」「資料」「提出」「締切」「締め切り」「期限」「用意」「準備」「持ち物」「必要」（件と同じ語）を含む文を、やること候補にする
- 「10/20 まで」「10月20日（火）までに」のような期限があればその日、無ければ予定の日を期限にする
- 1 つの予定から複数の候補を出してよい（件は 1 件だけだったが、通知には持参物と提出が並ぶことが多いため）

## 画面

### 予定アプリ
- 読み取りボタンの並びに「📁 ファイルから読む」を足す
- 1 件のとき: 今の「読み取った予定（確認して登録）」を使う
- 複数件のとき: 今の「手帳から読み取った予定」と同じ、チェックを付けてまとめて登録する画面を使う。見出しは「ファイルから読み取った予定」
- 各予定の下に、見つかったものだけ次を出す
  - ⚠️ 注意: 「10:00 の『○○』と重なります」「前の予定（△△、別の場所）から 10 分しかありません」「10/15 は水曜ですが、通知には木曜とあります」
  - ☎️ 連絡先: 電話・メール。「メモに入れる」のチェック（最初はオン）
  - ✅ やること候補: チェックを付けたものを、予定の登録と同時に「書類・やること」へ入れる
- 予定一覧の上に「気づいたこと」: これから 30 日の重なり・移動時間不足（壱師の予定と iPhone カレンダーの予定の両方）。それぞれ「この指摘を消す」。指摘が無いときは欄ごと出さない
- 予定の詳細で、メモの中の電話番号・メールアドレスを押せるようにする（`tel:`・`mailto:` のリンク。端末の電話・メール App が開くだけで、壱師からは送らない）
- 予定が 1 件も見つからないときは、取り出した文字を見せて「手入力」に進めるようにする

### 書類・やること（旧 書類・回覧トラッカー）
- 名前を「書類・やること」に変える。変える場所: 画面の題名と見出し、`manifest.webmanifest` の `name`・`short_name`、トップ画面のアプリ名と説明、`apps/README.md`。フォルダ名 `docs-tracker` と保存の鍵 `docs-tracker.v1` は変えない（保存データとキャラクター写真の結び付けを保つため）
- 上に「書類・やること｜メモ」の切り替えを置く
- 種別に「やること」を足す。予定から入れたものは、メモに「予定: ○○（10/22）」と書く
- メモのタブ
  - 文字で書く欄と「🎤 話してメモ」ボタン
  - メモの一覧（新しい順）。編集・削除ができる
  - メモに日付や「〜までに」があれば「予定に入れる」「やることにする」ボタンを出す
  - 「予定に入れる」: メモの文字を `meeting.js` で読み、予定アプリの 1 件の確認画面を開く
  - 「やることにする」: 書類・やることの入力欄に、件名・期限を入れた下書きを作る
  - 移したあともメモは残し、「予定に入れた」「やることにした」の印を付ける
- Watch の「期限が近いもの」には、今の仕組みのまま種別「やること」も出る

## データ

| データ | 保存先 | 形 |
|---|---|---|
| やること | `docs-tracker.v1` の `items` | 今の項目と同じ形。`kind: "やること"`、元の予定の識別子 `scheduleId`（無ければ空） |
| 自由メモ | `docs-tracker.v1` の `memos`（新設） | `{ id, text, createdAt, updatedAt, movedTo: ["schedule"｜"todo"] }`。古いデータに `memos` が無ければ空の配列として読む |
| 予定の連絡先 | `schedule.v1` の予定のメモ欄 | 新しい項目は作らず、メモの文字として入れる（カレンダーにもそのまま写る） |
| 消した指摘 | `schedule.v1` の `dismissedHints`（新設） | 指摘の鍵の配列。古いデータに無ければ空 |

- 今の保存データは書き換えずに読めること（`memos`・`dismissedHints`・`scheduleId` が無くても動く）
- メモから予定アプリへの受け渡しは、「撮る」から予定アプリへ送るときと同じ仕組みを使う

## 安全と失敗したとき

- 端末の外にデータを送らない。ファイル・メモ・音声はすべて iPhone の中で処理する
- 読み込んだ Word・Excel・PDF は保存しない。文字を取り出したら捨てる。共有で届いたファイルのコピーも読み終えたら消す
- 音声認識は Apple の音声認識に「端末内のみ」（`requiresOnDeviceRecognition = true`）を必ず付けて使う。端末内で日本語が使えない iPhone では「この端末では使えません」と出し、サーバーでの認識には切り替えない。録音したデータは保存しない
- 新しく必要になる許可: マイク・音声認識（初回だけ）。`Info.plist` に理由の文（「話した内容をメモにするため。音声は端末の外に送りません」）を書く。ファイルの読み込みに許可は要らない
- 読めないファイルは「このファイルは読めませんでした（理由）」と出して何も登録しない
- 取り出しの結果は必ず人が確かめてから登録する（通知や予定表の書き方は文書ごとに違うため、確実に読める前提に立たない）

## テスト

- Web 側の部品（`contacts.js`・`suggest.js`・`todos.js`・`scheduletable.js`・メモの日付の読み取り）は、`apps/tests/*.test.mjs` と同じ形でブラウザなしに確かめる
- Swift の文字の取り出しは、画面に依存しない部分を Mac 上でコンパイルして、架空の見本ファイル（会議通知 1 件の docx、行事予定表の xlsx と docx、文字のある PDF、スキャン PDF）を読ませて確かめる。見本は `apps/tests/fixtures/` に置き、架空の名前・番号だけを使う
- Swift 全体は `xcodebuild … CODE_SIGNING_ALLOWED=NO build` でコンパイルを通す
- 画面は Playwright で確かめる: ファイルから読んだ結果（Swift の代わりに見本の結果を渡す）の確認画面、注意・連絡先・やること候補、「気づいたこと」と「この指摘を消す」、名前の変更、メモのタブと「予定に入れる」「やることにする」
- 今あるテストがすべて通ること
- iPhone 実機（壱師）で確かめる: 「ファイル」App からの読み込み、メール添付からの共有、スキャン PDF、音声メモ（機内モードでも動くこと）、メモから予定・やることへの移動、Watch に「やること」の期限が出ること

## 作る順番（1 つの計画の中の段階）

1. Web 側の部品 4 つ（連絡先・提案・やること候補・表の読み取り）とテスト
2. 「書類・やること」への名前変更、種別「やること」、メモのタブ（文字だけ）
3. 確認画面への注意・連絡先・やること候補、予定一覧の「気づいたこと」、メモの電話・メールのリンク
4. iPhone 側: DocumentReader（ファイル選択・共有の受け取り・文字の取り出し）と「ファイルから読む」
5. iPhone 側: SpeechMemo（端末内のみの音声入力）と「🎤 話してメモ」
6. iPhone 実機で確認 → PR

各段階でテストを通してから次へ進む。作業ブランチは `feat/kudan-reader`。書く作業は Codex、確認・ビルド・iPhone への転送・手直しは Claude（スキル `build-app`）。

## この計画で扱わないこと

- 端末内 AI（説明・AI 秘書・壁打ち・ブレスト）と履歴（2-4）
- 名刺・連絡先の読み取り
- iPhone の「リマインダー」App への登録、やることの通知
- 古い形式の .doc・.xls、パスワード付きのファイル
