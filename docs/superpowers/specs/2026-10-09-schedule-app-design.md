# 予定アプリの新設と備蓄の削除 設計書（計画 2-1・2-2）

作成 2026-10-09。壱師アプリと件 V2 の統合（案A＝件の機能を壱師へ移す）の計画 2 を 4 つに分けたうちの 2-1 と 2-2。
2-3（件の読み取り機能）と 2-4（端末内 AI と履歴）は別の設計書で扱う。

## 目的

1. 使っていない「備蓄・消耗品」をなくし、トップをすっきりさせる（2-1）
2. 書類トラッカーを「書類・回覧」と「予定」に分け、件の機能の置き場所になる「予定」アプリを作る（2-2）

## 決まったこと（利用者との確認 2026-10-09）

- 件の機能は、今の「撮る」の流れに足す（案 A）。AI 秘書と履歴は、新しい予定アプリの中に置く（2-4）
- 備蓄・消耗品は **アプリごと削除** する（データは空）
- Watch の買い物リストは **冷蔵庫の分だけ** にする
- 書類トラッカーは「書類・回覧」と「予定」に **分ける**
- 予定アプリは「一覧」と「カレンダー」を **切り替え** られる
- iPhone のカレンダーの予定も、予定アプリに **一緒に表示する**（見るだけ）
- 件の「メモ」は、予定ごとのメモ欄と、書類の種類「手書きメモ」として扱う（2-3・2-4 で使う）

## 2-1. 備蓄の削除と買い物リスト

### 消すもの・外すもの

| 場所 | すること |
|---|---|
| `apps/stock/`（フォルダごと） | 削除する |
| `apps/index.html` | 備蓄のアイコン（`<a class="app" href="stock/index.html">`）を外す |
| `mobile/scripts/build-www.mjs` | 組み立ての対象の一覧から `stock` を外す |
| `apps/shared/watch.js` | `stockShopping()` を外し、買い物リストは `fridgeShopping()` だけにする |
| `apps/shared/inbox.js` | 送り先 `stock` を外す（送り先は冷蔵庫だけ） |
| `apps/kakeibo/index.html` | 「備蓄へ送る」ボタン（`sendStock`）を外す |
| `apps/shared/character.js`・`character-settings.js` | 枠 `stock` を外し、枠 `schedule`（見出し「予定」）を足す |
| `apps/tests/*`、`apps/README.md` | 備蓄に触れている部分を直す |

- 端末に残っている備蓄のデータ（localStorage の `stock.v1`、キャラクター写真の `stock` 枠）は、トップ画面を開いたときに1回だけ消す（中身が空であることは利用者が確認済み）
- **ファイルを消す前に、対象の絶対パスの一覧を利用者に示し、明示の承諾を得てから消す**（AGENTS.md のルール）

## 2-2. 予定アプリ

### 画面（`apps/schedule/index.html`、新規）

- トップに「予定」のアイコンを足す（書類トラッカーのすぐ下）。アイコン画像は書類トラッカーの画像を元に作り、利用者が後で差し替えられるようにする
- 上部に「一覧」「カレンダー」の切り替えボタン。最後に選んだほうを覚えておく（localStorage の `schedule.view`）
- **一覧**: 「今日」「明日」「今週」「それ以降」「過ぎた予定（直近 7 日）」の見出しで分け、日付・時刻の順に並べる
- **カレンダー**: 月のマス目（月曜始まり）。予定のある日に点を付け、日を押すとマス目の下にその日の予定を出す。前の月・次の月へ移れる
- **iPhone のカレンダーの予定**: 一覧とカレンダーの両方に並べる。左端に色の帯を付けて、予定アプリの予定と見分けられるようにする。押しても編集はできない（見るだけ）。読むのは今日から 60 日先まで。アプリ版でだけ読み、ブラウザでは出さない
- **予定アプリの予定**: 登録・編集・削除、カレンダーへの書き込み（ics の書き出しを含む）は、今の書類トラッカーの「会議」の機能をそのまま移す。会議の読み取り確認欄（会議の通知を撮ったあとの確認）と、手帳の読み取りの登録先も、予定アプリに移す
- キャラクター写真の背景は、枠 `schedule` を使う

### データ

- 保存場所: localStorage の `schedule.v1`。形は `{ version: 1, items: [...], calIds: {...} }`（`calIds` はカレンダーに書き込んだ予定との対応表。書類トラッカーから写す）
- 1 件の形は、今の書類トラッカーの会議・予定の項目をそのまま使う（`id`・`kind`（"会議" または "予定"）・`title`・`dest`（場所）・`dueOn`（日付）・`note`・`planKey`・`icsSeq`・`createdAt` など）。書類にしか使わない `status`・`priority`・`doneAt` も、引っ越しの間違いを防ぐため、そのまま持たせる

### 引っ越し（1 回だけ）

- 予定アプリまたはトップ画面を開いたとき、`schedule.v1` がまだ無ければ行う
  1. `docs-tracker.v1` を `docs-tracker.v1.backup-2026-10` に写す（既にあれば写さない）
  2. `kind` が「会議」または「予定」の項目を `schedule.v1` に移す
  3. `docs-tracker.v1` から、移した項目を外して保存する
- 途中で失敗したら、`docs-tracker.v1` は変えずに終える（次に開いたときにやり直す）
- 引っ越しの処理は `apps/shared/schedulemove.js` に置き、トップ画面と予定アプリの両方から呼ぶ

### 書類・回覧トラッカー（今の `apps/docs-tracker/`）

- 名前を「書類・回覧トラッカー」にする（画面の見出し、トップのアイコンの名前と説明）
- 種別の選択肢から「会議」「予定」を外す。会議の読み取り確認欄、手帳の読み取りの登録、会議をカレンダーへ書き込む機能を外す（予定アプリへ移したため）
- フォルダ名 `docs-tracker` と QR の Deep Link（`myproject://docs?id=...`）は変えない（貼ってある QR が使えなくなるのを防ぐため）

### つながる部分

| 部分 | 変えること |
|---|---|
| トップの「撮る」（`scanrouter.js`） | 会議の通知と手帳は `schedule/index.html` へ送る。レシートは家計簿へ（変えない） |
| Watch・ウィジェット（`watch.js`） | 会議・予定は `schedule.v1` から、期限は `docs-tracker.v1` から読む。Watch の表示の形は変えない |
| `calendarread.js` | 予定アプリの形に合わせて直す（中身の考え方は変えない） |
| `build-www.mjs` | 組み立ての対象に `schedule` を足す |
| キャラクター写真 | 枠 `schedule` を足す（2-1 で `stock` と入れ替え） |

## テスト

- 新しいテスト（ブラウザ不要）:
  - `apps/tests/schedulemove.test.mjs`: 会議・予定だけが移る、書類は残る、控えができる、2 回目は何もしない、途中で失敗したら元のまま
  - `apps/tests/schedule.test.mjs`: 一覧の見出しの分け方（今日・明日・今週・それ以降・過ぎた予定）、カレンダーのマス目（月曜始まり、月またぎ）
- 既存のテストを新しい形に合わせて直す（`watch`・`scanrouter`・`ics`・`character`・`build`・`smoke`・`pwa`・`kakeibo`）。直したあと、元からある `smoke` の 2 件の失敗以外は通ること
- iPhone で確かめる: 引っ越しで会議・予定が予定アプリに移ること、書類は書類・回覧トラッカーに残ること、カレンダーの予定が見えること、「撮る」で会議・手帳が予定アプリに入ること、Watch に会議と期限が出ること
