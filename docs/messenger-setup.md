# ふたりのメッセージ — 使い方と用意のしかた

相手と自分しか読めない形（エンド・ツー・エンド暗号化）で、文章と写真をやりとりするアプリ。
iPhone・Android の両方でアプリとして使える。

- アプリ本体: `apps/messenger/`
- 中継サーバー: `server/`（[server/README.md](../server/README.md)）

---

## はじめに — できること・できないこと

**できること**

- 本文と写真は、送る端末の中で暗号化される。**中継サーバーの運営者にも、通信を覗いた人にも読めない**
- 1通ごとに鍵を作り直すため、いまの鍵が漏れても**過去のメッセージは解読できない**（前方秘匿性）
- 会話ごとに「消えるメッセージ」を設定でき、双方の端末から自動で消える
- 1通だけ「1回だけ」を選ぶと、相手が1度開いた時点で消える

**できないこと（正直にお伝えします）**

- **この暗号処理は第三者の監査を受けていません。** 標準的な方式（ECDH P-256 / AES-256-GCM）に沿って作っていますが、
  Signal のように何年も専門家に検証されたものではありません。
  日常の連絡を他人に見られないようにする用途向けです。**身の安全に関わる重大な秘密には Signal をお使いください**
- **「誰から誰へ、いつ、どれくらいの大きさの暗号文が流れたか」は中継サーバーに残ります**（本文と写真は残りません）
- **画面の撮影までは防げません。** 消える機能は、相手が同じアプリを正しく使っている場合にだけ働きます。これは他のアプリでも同じです
- **端末を無くすと会話は復旧できません。** 鍵は端末の中だけにあり、どこにも預けていないためです

## 1. 中継サーバーを用意する

相手が電源を切っているときにメッセージを預かる役が要る。**中身は暗号のままなので読まれない。**

```
node server/server.mjs
```

インターネット越しに使うには、常時動いていて `https://` で開ける場所に置く。
無料枠のある Render などが使える。詳しくは [server/README.md](../server/README.md)。

用意できたら、ブラウザでその場所を開いて、次のような文が出れば成功。

> 暗号化メッセージの中継サーバーです。預かっているのは端末側で暗号化された封筒だけで…

> **`https://` が必須です。** `http://` のままでは iPhone / Android のアプリから接続できません。

## 3. はじめの設定

1. 相手の画面に出る**自分の名前**を入れる
2. **中継サーバーの場所**（`https://…`）を入れる
3. 「この内容ではじめる」を押す

このとき、この端末だけの鍵が作られる。**鍵はどこにも送信されない。**

## 4. 相手を登録する（1回だけ）

コードを2往復させる。コードに秘密鍵は入っていないので、LINE・メール・口頭など何で渡してもよい。

| | 誘う側（Aさん） | 誘われる側（Bさん） |
| --- | --- | --- |
| ① | 「相手を追加する」→「招待コードを作る」 | |
| ② | 出てきた文字列を B さんに渡す | |
| ③ | | 「相手を追加する」→ 貼り付け →「読み込む」 |
| ④ | | 出てきた**返信コード**を A さんに送り返す |
| ⑤ | 返信コードを貼り付け →「読み込む」 | |

これで双方の一覧に相手が現れる。**④を送り返さないと A さん側で会話が始まらない。**

> 招待コードには中継サーバーの場所も入っている。B さんがまだ設定していなければ自動で合わせる。

## 5. 安全番号を確かめる（推奨）

コードの受け渡しの途中で、悪意のある人がすり替える（中間者攻撃）ことは理屈のうえでは可能。
これを見破るために、トーク画面の「安全番号」を押し、**電話や対面など別の手段で**60桁を読み合わせる。
一致していれば、確かに本人とつながっている。

## 6. メッセージを送る

- 文章を入力して「送信」（パソコンでは Ctrl+Enter でも送れる）
- 「写真」で画像を添える。送る前に自動で小さくする（長辺1600ピクセル・約900KB以下）
- 圏外のときは「未送信」と表示され、**回線が戻ると自動で送り直す**

## 7. 消えるメッセージ

トーク画面の「消える」を押して設定する。**既定はオフ（消えない）。**

| 設定 | 動き |
| --- | --- |
| オフ（消えない） | 端末を消すか、履歴を消すまで残る |
| 1時間後 / 8時間後 / 1日後 / 1週間後 / 4週間後 | その時間が過ぎたら双方の端末から自動で消える |

- 数え始めは、**送った側は送信したとき、受け取った側は端末に届いたとき**
- 設定は相手にも自動で伝わり、双方の画面に「〇〇が…にしました」と残る
- **オフに戻すと、まだ消えていないメッセージの消える予定も取り消される**（＝残る）
- 設定より前に送ったメッセージには、あとから期限は付かない

### 1回だけのメッセージ

入力欄の下の「1回だけ」を押してから送ると：

- 受け取った側は「開く」を押したときだけ中身が見え、閉じると端末から完全に消える（「表示済み」の跡だけ残る）
- **送った側には最初から本文を残さない**（相手が開いたかどうかを知る手段を持たないため）
- 送信のたびに自動で解除される（誤送信を防ぐため）

### 履歴をまとめて消す

「消える」→「この会話の履歴を消す」で、**この端末の**履歴を消す。相手側には残る。
端末ごと消したいときは、設定 →「すべて消す」。

## 8. 機種変更するとき

設定 →「JSONで保存」で書き出し、新しい端末で「JSONから読み込み」。

> **書き出したファイルには秘密鍵とすべての履歴（写真を含む）がそのまま入ります。**
> 他人に渡すと過去と今後のメッセージを読まれます。自分だけが管理できる場所に置き、移行後は削除してください。

## しくみ（技術的な内容）

### 鍵の作り方

| 場面 | 方式 |
| --- | --- |
| 最初の共通の秘密 | X3DH 相当（3回の ECDH P-256 を HKDF-SHA256 で束ねる） |
| 1通ごとの鍵 | Double Ratchet 相当（送受信のたびに根の鍵と鎖の鍵を進める） |
| 本文の暗号 | AES-256-GCM（改ざんも検知する） |
| 中継サーバーへの本人確認 | ECDSA P-256 の署名（時刻入りで、使い回しを防ぐ） |

いずれもブラウザと OS に最初から入っている Web Crypto API のみで実装している（`apps/messenger/crypto.js`）。
追加のライブラリは使っていないため、コードをすべて読んで確かめられる。

### 順番が入れ替わって届いた場合

飛ばされた番号の鍵を一時的に取り置き、あとから届いたぶんも開ける（最大500通ぶん）。
使った鍵はその場で捨てるため、**同じメッセージを二度開くことはできない**。

### 確かめかた

```
node apps/tests/crypto.test.mjs        # 暗号処理（ブラウザ不要）
node apps/tests/relay.test.mjs         # 中継サーバー（実際に起動して確認）
node apps/tests/messenger.smoke.mjs    # 2画面で実際にやりとりさせる（Playwright）
```

## 困ったとき

| 症状 | 確かめること |
| --- | --- |
| 「未接続」のまま | 設定 →「つながるか確かめる」。中継サーバーが動いているか、`https://` になっているか |
| 相手が一覧に出ない | 返信コードを送り返したか（手順④）。両者が同じ中継サーバーを指しているか |
| 送っても届かない | 相手もアプリを開いて「接続済み」になっているか。7日を過ぎた封筒は中継側で削除される |
| 「メッセージを開けませんでした」と出る | 相手がアプリのデータを消して作り直した可能性がある。相手を削除し、もう一度登録し直す |
| 安全番号が一致しない | **使うのをやめ、別の手段で本人に確認する。**登録し直すこと |
