# 日常アプリ

ブラウザだけで動く小さなアプリ。サーバー側の処理もアカウント登録もなく、データは端末の中だけに残る。

| アプリ | 用途 | 場所 |
| --- | --- | --- |
| 冷蔵庫の在庫・賞味期限管理 | 食材の期限管理、バーコードでの登録、食品ロスの記録 | `apps/fridge/` |
| 書類・回覧の期限トラッカー | 提出期限のある書類・回覧・申請の管理 | `apps/docs-tracker/` |

## iPhone で使う（GitHub Pages で公開する）

カメラ（バーコード読み取り）とオフライン起動は、ブラウザの決まりで `https://` でしか動かない。
そのため、このリポジトリでは **GitHub Pages に公開して iPhone から開く**方法をとる。

`.github/workflows/pages.yml` が `main` への変更を検知して自動で公開する。
公開されるのは **2つのアプリとトップページだけ**で、テストや設定ファイルは含まれない。

### 初回だけ必要な操作（リポジトリの管理者）

1. GitHub の **Settings → Pages** を開く
2. **Source** を「GitHub Actions」にする
3. `apps/` 以下の変更を `main` に反映する（Actions タブで公開の進行を確認できる）

公開先のURL：

| | URL |
| --- | --- |
| トップページ | `https://akihitofujioka-bit.github.io/myproject/` |
| 冷蔵庫 | `https://akihitofujioka-bit.github.io/myproject/fridge/` |
| 書類トラッカー | `https://akihitofujioka-bit.github.io/myproject/docs-tracker/` |

### iPhone のホーム画面に追加する

1. **Safari** で上のURLを開く（Chrome など他のブラウザからは追加できない）
2. 下部の共有ボタン（□に↑）→「ホーム画面に追加」
3. 追加されたアイコンから起動する

初回にバーコードを読み取るとき、カメラの使用許可を聞かれるので「許可」を選ぶ。
Android の Chrome では、メニューの「アプリをインストール」から同じことができる。

### 公開範囲について

- 公開されるのは**アプリの画面（HTML・JavaScript・アイコン）だけ**。入力したデータは各自の端末に残るので、公開されない
- このリポジトリはもともと公開設定のため、Pages の有効化によってコードの公開範囲は変わらない
- URLを知っていれば誰でもアプリの画面自体は開ける（他人が開いても、その人の端末には何のデータもない状態で始まる）

## パソコンだけで試す場合

各フォルダの `index.html` をダブルクリックすれば、カメラとホーム画面追加を除く機能が使える。
同じネットワークの端末から見るなら、リポジトリ直下で次を実行して `http://<IPアドレス>:8080/apps/fridge/` を開く。

```
npx http-server . -p 8080
```

## バーコード読み取り（冷蔵庫アプリ）

下部の「バーコードで追加」からカメラを起動し、商品のJANコードを読み取る。

**読み取りの仕組み**は2段構え。

1. 端末が `BarcodeDetector` API に対応していれば、それを使う（Android の Chrome など。OS標準の処理で精度が高い）
2. 非対応の端末（iPhone の Safari など）では、`apps/fridge/ean.js` の自前デコーダで読む

どちらでも読めないときのために、**番号の手入力**を常に用意している。誤読を防ぐため、
同じ番号を2回続けて読み取れたときだけ確定する。

**商品名は端末の中で覚える。** 外部の商品データベースには問い合わせない（通信を一切しない設計のため）。
そのため、初めて読むバーコードは品名を1回だけ入力する必要がある。次回から同じ商品は
品名・単位・保管場所が自動で入る。覚えた対応は「JSONで保存」に含まれるので、端末を移しても引き継げる。

**制約**：自前デコーダは JAN-13／JAN-8／UPC-A に対応。暗い場所、光の反射、曲がった面、
手ブレでは読み取れないことがある。読めないときは明るい場所で、バーコードを枠いっぱいに、
端末を10〜15cm離して静止させる。それでも読めなければ番号を手入力する。

## データの保存場所と安全性

- データは**開いたブラウザの localStorage にのみ**保存される。外部への送信は一切行わない（通信するコードを含まない）
- したがって**ブラウザや端末が変わるとデータは引き継がれない**。「JSONで保存」で書き出し、移行先で「JSONから読み込み」する
- ブラウザの「閲覧履歴・サイトデータの削除」を実行するとデータも消える。定期的な書き出しを勧める
- シークレットウィンドウでは、閉じた時点でデータが消える
- **共用パソコンでは使わない**。使う場合は終了時にサイトデータを削除する
- 書類トラッカーには、個人が特定できる情報（氏名・住所・個人番号など）を入力しない。書類名は「〇〇申請書（△△課分）」のような表記にとどめる
- 公開する場所に置く場合でも、**公開されるのはアプリの画面だけで、入力したデータは公開されない**（データは各自の端末に残るため）

## 朝のブリーフとの連携

書類トラッカーの「JSONで保存」で書き出したファイルを `data/deadlines.json` として置くと、`/brief`（朝のブリーフ）が今日の締切として拾う。
冷蔵庫アプリの書き出しを `data/fridge.json` に置き、`brief.config.json` の `fridge.enabled` を true にすると、期限が近い食材も1行だけ添えられる。

`data/` の中身は業務情報を含みうるため git 管理対象外にしてある。

## 動作確認

```
node apps/tests/ean.test.mjs     # バーコード読み取り（ブラウザ不要）
node apps/tests/smoke.mjs        # 画面操作ひととおり
node apps/tests/pwa.test.mjs     # ホーム画面追加・オフライン起動
```

後ろ2つは Playwright を使う（`npm i -D playwright && npx playwright install chromium`）。
アプリ本体は依存ライブラリなしで動き、Playwright を使うのはテストだけ。

## つくりの方針

- 依存ライブラリなし。ビルド不要。通信なし
- 端末の設定に合わせてダークモードに対応
- 画面幅に合わせて可変。入力欄は16px以上（iOSで勝手に拡大されないため）
- アプリを更新したときは、次に開いたときに反映される（Service Worker がまずキャッシュを返すため）
